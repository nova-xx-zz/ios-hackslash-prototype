# ios-hackslash-prototype

ゲーム名は「ソードクレスト（Sword Crest）」（仮決定）。iPhone (Safari) で遊べる、5人パーティ・オート戦闘のハクスラダンジョンクロールのプロトタイプです。ビルド不要のバニラ HTML/CSS/JavaScript で作られています。

> 特定タイトルの仕様を模倣したものではなく、「5人パーティ／速度依存のオート戦闘／転職システム」というジャンル共通の要素を、オリジナルの名称・データで実装したものです。ジャンルやゲームシステム自体は著作権の対象ではありませんが、固有名詞・グラフィック・文章表現は独自のものにしています。
>
> 開発経緯: v1はリアルタイム自動戦闘、v2はドラクエ/FF風のコマンド選択ATBバトルでした。今回は「速度ステータスに応じて行動間隔が変わる、5人フルオートのハクスラ」という要望に合わせて戦闘エンジンを作り直しています。

## 遊び方

`index.html` をブラウザで開くだけで起動します。ローカルで試す場合は簡易サーバーを立ててください。

```
python3 -m http.server 8000
# http://localhost:8000 を iPhone Safari または PC ブラウザで開く
```

- **セーブ/ロード**: 所持キャラ全員（レベル・ジョブ・種族・装備・スキル設定など）・所持品・出撃中チーム・クリア済みダンジョンを端末（localStorage）に自動保存する。キャラ詳細やパーティ編成の操作、ダンジョンクリア/全滅のたびに保存されるほか、タブを閉じる／バックグラウンドに回す（visibilitychange）タイミングと20秒ごとの定期保存でも保存するため、ブラウザを閉じても進行状況が失われない。端末の保存容量不足などで保存に失敗した場合は、画面上部に赤い警告帯が出る（ゲームの進行は止まらず、次に保存が成功した時点で警告は消える。画面上部のボタンを覆い続けないよう8秒で自動的に隠れ、タップで閉じた後は5分間は出し直さない）。保存データが無い場合（初回起動）だけ、Lv.1の5人スターターパーティから始まる
- **タイトル画面**: 冒険者ギルドの机に置かれた剣・紋章・古地図のオリジナル背景に、上寄りの金色2段ロゴ `SWORD / CREST` と「ソードクレスト」を重ねる。下寄りの `Tap to Start` はゆっくり明滅し、画面をタップすると探索画面へ進む。右上に手紙型のお知らせ（未読バッジ）とバージョン、下部に「設定/お知らせ」「データ保存」「データ復元」を配置。保存は既存のクラウドバックアップ、復元は設定画面で内容を確認して確定する。安全領域を避け、短い画面ではロゴと余白を縮める。動きを減らすOS設定では背景と開始ボタンのアニメーションを停止する
- **探索画面**: タイトルと同じ青緑・古金色で統一したギルド背景、職業紋章付きの仲間カード、金色の線画ナビゲーションを表示する。まだ出発していないパーティには「冒険の準備」と「マップを開く」を表示し、未編成なら「仲間を編成する」に切り替える。探索中・帰還後は暗いログカードで戦闘と獲得品を読みやすく表示する。下部の「編成／探索／書物／設定」が常設ナビゲーションの起点で、図鑑・設定の「もどる」も探索画面に戻る。短い画面では案内をスクロールでき、職業紋章を省いてログ欄の高さを確保する
- **設定画面**: 探索画面下部の「設定」から開く。現状はバージョン表示のみの最小限の雛形で、今後ここに設定項目を追加していく予定
- **冒険者ギルドからのお知らせ**: タイトル右上の手紙アイコン（未読があれば赤丸バッジ表示）、または設定画面から開ける。「お知らせ」（日付降順の一覧、カテゴリは📢お知らせ／✨アップデート／🔧調整／🔮予告、タップで詳細モーダル）と「今後の予定」（公開済み／開発中／公開予定のロードマップ）の2タブ構成。詳細を開いた告知だけ既読になり、次回起動時から再表示されない。起動時に未読の告知があれば自動で1件だけモーダル表示し、オフライン進行の「おかえりなさい」モーダルとは重ねずキューで順番に表示する。告知データは`data/announcements.js`、予定表は`data/roadmap.js`にオリジナルの内容で定義している
- 段階公開中の機能は`FEATURE_FLAGS`による機能フラグでON/OFFを管理し、フラグがOFFの間はUI・ドロップ・戦闘効果のいずれにも影響しない。**スキルツリー（固有ツリー＋汎用3枠、SP、分岐図UI）は公開済み**。スキルブック・鑑定所・一次職の極みは今後追加予定で、引き続きフラグOFF。セーブデータは`schemaVersion`を持ち、旧形式のセーブも自動的に移行される
- 所持キャラ全員が「ロスター」に入り、そこからI〜IVの4チーム（各最大5人）に振り分ける。**I〜IVの4チームは常時並行して探索できる**（表示していないチームも裏側でダンジョン探索を継続する）
- キャラクターは「種族×ジョブ」でステータスが決まる。種族はプレイヤー用8種（ヒトゾク/ハーフビースト/もりびと/いわびと/よあるきぞく/こうじん/せいれいぞく/きょじん）＋テイム対象のモンスター4種。各種族はステータス倍率に加えて、会心率・被ダメ軽減・吸収・経験値倍率・MP消費減・回復量増のいずれか1つのパッシブを持つ
- ジョブは基本職6種（せんし/まほうつかい/そうりょ/とうぞく/ぶとうか/あんこくし）＋上級職6種（けんごう/だいまどうし/だいしんかん/にんじゃ/けんせい/しにがみ）の計12種。上級職は対応する基本職をLv.50まで極めると転職できる。とうぞくは多段、ぶとうかは殴りながら回復もでき、あんこくしはHP吸収と闇魔法を使う
- **転職してもレベルは失われない**。キャラはジョブごとに独立したレベル/EXPを持ち、転職すると新しいジョブは(未経験なら)Lv.1から始まるが、以前極めたジョブに戻ればそのときのレベルからすぐ再開できる
- 戦闘は全員フルオート。各キャラは速度(SPD)に応じてたまるゲージが満タンになると自動で行動する
- 「パーティ編成」画面は一覧形式。「パーティ」セクションに第一〜第四のパーティが折りたたみ行で並び、開くとメンバーカードが横に並ぶ。「未編成」セクションには控えのキャラと、仲間を増やす「＋」タイルがある
- 出撃するパーティは行の「このパーティで出撃する」で切り替え、選択中の行には「出撃中」バッジが付く
- メンバーカードをタップするとキャラ詳細画面が開く。下部の「能力値／装備／スキル／ジョブ」タブで切り替える形式で、能力値タブは基本情報・所属パーティ・HP/MP/ATK/MAG/DEF/SPDの一覧、装備タブはスロット管理をまとめている。OFFにしたアビリティはオート戦闘のAIが選ばなくなる
- スキルタブは「アクティブ／パッシブ」の2セクションに分かれた行リスト表示。各行はアイコン・技名・ON/OFFトグル（丸ボタン）で構成され、未習得の技は行末に「Lv.◯で習得」とグレー表示される。アクティブ枠の行には優先度チップ（優先／通常／温存、タップで循環）も付き、パッシブ枠は種族特性が常時ONの静的表示で並ぶ。下部にはサブアビリティ①②と攻撃対象の優先度の設定も続く
- **敵の特性と属性**: 敵には特性（アンデッド＝聖属性以外が効きにくい／霊体＝物理が効きにくい／魔法耐性＝魔法が効きにくい／堅牢＝防御がとても高い）と属性（火・氷・水・風・土・闇・光など）がある。効きにくさはノーマル0.6倍・ハード0.3倍・エクストラは効かない、堅牢の防御は1.5／2.5／4倍。技にも属性（炎・氷・雷・聖・闇）があり、敵の属性で弱点1.5倍・耐性0.5倍。防御・攻撃・素早さを下げる技、味方の攻撃・魔力・防御を上げる技、味方の攻撃を聖属性にする技（聖なる加護）があり、オート戦闘AIは「効いている間に増える与ダメージ／減る被ダメージ」を見積もって使う（`js/core/battle.js`）。戦闘の始めに「特性: アンデッド」のようにログで知らせ、図鑑の詳細に特性・弱点・耐性を表示する
- **スキルツリー**: キャラ詳細画面の「ツリー」タブで確認できる。1キャラは「固有ツリー（ジョブの系統タグ＝せんし系統・まほうつかい系統など6系統ごとに固定1本、基本職と対応する上級職で共通、交換不可）」＋「汎用ツリー3枠（全ジョブ共通のツリーから、枠ごとに決まった2択でいつでも交換できる）」の計4本を同時に持つ。レベルアップで得るSP（`Lv-1`ぶん）はこの4本で共有する1つのプールから消費し、パッシブ効果や専用アクティブ技（固有ツリーのみ）のノードを習得していく。各ツリーはノードを線でつないだ本物の分岐図として表示され、ノードをタップすると、画面の下（タブの上）に説明・コスト・習得ボタンが固定で出る（スクロールしなくても習得でき、習得してもスクロール位置は変わらない）。ノードには前提（先に習得しておく必要のあるノード）や排他分岐（どちらか一方だけ選べる二択）があり、習得済みノードのパッシブ効果は既存の能力値・会心率・被ダメ軽減・回復量・消費MPの計算にそのまま合算される。アクティブ技のノードを習得すると、スキルタブの技一覧にも追加されてオート戦闘AIがそのまま使用する。汎用ツリー3枠は見出し横の「交換」ボタンから、もう一方の候補へいつでも切り替えられる（2回タップで確定）。交換すると、その枠に振ったSPだけリセットされ、固有ツリーや他の枠には影響しない（レベルアップで得たポイントが交換によって配分不能になる事態を防ぐための仕様。現状は無償・即時の簡易実装で、将来的にはスキルブックの入手・消費と結びつける予定）。ツリーの進行はキャラ・ジョブごとに個別管理のため、転職しても現在のジョブ以外のツリー進行は失われず、別ジョブに切り替えるとそのジョブ自身のSP・ノード習得状況になる。探索中／自動周回中のチームに所属するキャラはツリーの閲覧のみ可能で、ノード習得・枠交換はロックされる。モンスターや対応する系統タグを持たないジョブでは「ツリー」タブ自体が表示されない。**段とレベル**: マスには段があり、ジョブのLv20〜90で順に開く（左端に「Lv20」などを表示し、届いていないマスは🔒）。全部取るとSPはちょうど98（Lv99のSP）。後半のマスは能力値の割合（ATK+5%など）や、敵の特性への対策の技（鎧砕き・光の矢・聖なる加護・鬨の声など）。**振り直し**: 見出しの下の「ツリーを振り直す」で、そのジョブの4本ぶんのSPを全部戻せる（強化石を使ったSP×20個。探索中のチームは不可）。詳細は `docs/skill-tree-design.md`
- ジョブタブは「基本職／上級職」のカードグリッド表示。各カードはアイコン・Lv表示（未経験なら「未経験」）・EXPバーで構成され、現在のジョブは緑枠でハイライトされる。Lv.50に達したジョブのカードには★が付き、未解放の上級職カードは薄く表示されてタップしても反応しない。習得済み（Lv.1以上）または解放済みのカードをタップすればその場で転職できる
- サブアビリティは2枠。**実際にレベルを上げたことがあるジョブ**の技だけが候補になるので、いろいろなジョブを育てるほど選べる技が増え、ビルドの幅が広がる
- メンバーカードを**長押ししてドラッグ**すると、別のパーティ行や「控え」にそのまま移動できる。満員(5人)のパーティに重ねると枠が赤くなり、離しても移動せずメッセージが出る
- 「仲間を探す」または「＋」タイルからキャラ作成画面へ。なまえ・しゅぞく・ジョブがそれぞれ枠で区切られた行になっていて、しゅぞく・ジョブの行をタップすると詳細モーダルが開く。アイコン・説明文・能力値の星評価・アビリティ（またはしゅぞく特性）一覧に加えて、下部の候補アイコン列をタップするとモーダルを開いたまま他の候補に切り替えて見比べられ、「OK」で確定する（外側タップでキャンセル）。プレビュー欄にはステータス・種族特性・習得済みアビリティがその場で表示される（「ランダム」ボタンで全項目をまとめて振り直せる）。新しく作った仲間は既存メンバーのレベルに関わらず常にLv.1から始まる
- 「冒険に出る」から探索画面（ログ＋ドック）へ直接入る。まだダンジョンを選んでいない場合は「ダンジョン未選択」の状態でパーティ・ドックだけが表示され、案内文が出る。ドックの「マップ」を押すとダンジョン選択画面が開き、ノードをタップして出発すると同じ探索画面に戻って戦闘が進む（マップの「もどる」は常に探索画面に戻る）
- マップ画面ではダンジョンはノードとして地図上に配置され、クリアすると次のダンジョンが解放される（線が実線になり、ノードが緑の✓になる）。ノードの表示はダンジョン名のみで、ノードをタップして開く詳細パネルもダンジョン名・説明文・戦闘数だけのシンプルな内容にしている（推奨レベルや出現モンスターの一覧は表示しない）
- 探索画面は上がテキストログ、下がドック（ダンジョン進行バー／パーティ5人のHP・MP・行動ゲージ／自動周回設定／再出撃・マップ・編成ボタン／I〜IVのチームタブ）
- **複数パーティの同時探索**: I〜IVの4チームはそれぞれ独立にダンジョンへ出撃でき、常時並行して進行する（画面に表示していないチームも裏側でATB戦闘が進む）。探索画面下部のチームタブは「今どの結果を見ているか」を切り替えるだけの表示切り替えで、探索の進行そのものには影響しない。探索中のチームはタブに●が付き、パーティ編成画面の該当パーティにも「探索中」バッジが出る。ログ・進行状況・自動周回はチームごとに完全に独立している
- **自動周回**: チームごとに、直前に挑んだダンジョンへ指定した回数（x1/x3/x5/x10/x20/x50。ショップで買うとx100）だけ自動で再出撃し続ける機能。回数チップを選んで「自動周回開始」を押すとすぐに1周目が始まり、踏破するたびに少し待ってから同じダンジョンへ再出発する（「n/m 周」の進捗表示に切り替わる）。設定した周回数に達すると自動的に停止し、途中で全滅した場合もその場で自動的に停止する（全滅時は毎回HP/MPが全回復してから再出発するため、そのまま回し続けると事故が起きやすいための安全装置）。稼働中は「停止」でいつでも中断できる。探索中のチームは、そのチームの編成・装備・スキル・転職・合成の変更のみロックされる（パーティ編成画面や詳細画面は開けるが、探索中チームの部分は表示のみになる）。他の待機中チームの編成はいつでも自由に変更できる（自動分解の設定は、どこかのチームが探索中・自動周回中の間は変更できない）。選んだ周回数は端末に保存され、次回も同じ設定から始められる
- **自動周回の完了通知（iOSアプリ版のみ）**: 自動周回中にアプリを離れると、チームごとに「残りの周回数×1周の目安の時間」後（精算できる上限の8時間を超える時は8時間後）に、端末のローカル通知で知らせる（`@capacitor/local-notifications`。サーバーは使わない。`js/core/notices.js`・`js/ui/notify.js`）。離れている間は実際には戦っていないので、通知は終わっている頃の目安（全滅で止まったかは開くまで分からない）。アプリに戻る・開き直すと、まだ届いていない通知は取り消す。通知の許可は初めて自動周回を始めた時に求め、設定画面の「自動周回の完了通知」でON/OFFできる（アプリ版だけ表示）。ブラウザ版では何もしない
- **自動周回のオフライン進行**: このゲームはサーバーを持たない静的サイトのため、タブを閉じている・バックグラウンドの間に実際の戦闘を進め続けることはできない。その代わり、自動周回が稼働中の状態でアプリを離れる（タブを閉じる/バックグラウンドに回す）と離れた時刻を記録しておき、次に開いた時に経過時間（最大8時間ぶんまで。それを超えた分は切り捨て）から「何周できたはずか」をまとめて計算する。離れていた間の各周回は、通常プレイと同じ戦闘エンジンでそのチームのキャラ（装備・スキルツリー・技の設定込み）を実際に戦わせて決め、戦闘ごとにかかった時間を離れていた時間から差し引いていく（時間内に終わらなかった周は数えない）。道中の泉の回復と罠のダメージも反映する（石碑の加護は省略するため、実際のプレイよりわずかに厳しめ）。報酬は既存のEXP・ドロップ・自動分解・テイム抽選の計算式をそのまま再利用して一括反映し（遭遇した敵は図鑑にも登録される）、**複数チームが同時に自動周回中だった場合は、チームごとに独立して計算し、モーダルにもチームごとの結果が並ぶ**。オフライン中の周回でも全滅が起こり得て、全滅した周はドロップ・テイムを持ち帰れず自動周回も停止する。EXPは通常プレイと同じく勝利した戦闘ごとに付与されるため、全滅した周でもそれまでに勝った戦闘のEXPは残る（個々の戦闘不能は再現しないため、EXPはパーティ全員に入る）。オフライン分の反映後、自動周回は一旦停止状態になるので、続けたい場合はチームごとに「自動周回開始」を押し直す。離れていた時間が1周ぶんに満たなかった場合も、その旨をモーダルで知らせる。ページを閉じずにバックグラウンドから復帰した場合も同じ精算を行う（離れる直前の周回は中断扱いになり、その周の未確定ドロップは持ち帰れない。1周ぶんの時間が経っていなければ中断せず続きから再開する）。精算した報酬と自動周回の停止は1回の保存でまとめて確定し、精算済みかどうかはセーブの中の自動周回が止まっていることで判定する（別キーの印は使わない）。保存容量不足などで保存できなかった場合は、端末には精算前のセーブが残るので、報酬が二重になったり失われたりせず、保存できるまで再試行し、保存されないまま閉じたら次回起動時に精算し直す
- ログは出来事ごとの色分けカードになっていて、「敵が現れた！」（赤）には敵の残り状況と戦闘中のダメージ行が積まれ、最後に「踏破した！」（紫）か「全滅した・・・」（灰）のカードが出る。**ログは出撃するたびに消えず、チームごとに直近20周分の履歴が残る**（それより古い周回のログは自動で間引かれる）ので、少し前の周回の結果も見返せる
- 戦闘と戦闘の間には約6割の確率で道中イベントが起きる。宝箱（緑・アイテムか空っぽ）、罠（橙・落とし穴で1人/毒ガスで全員がダメージ。ただし罠では戦闘不能にならない）、清らかな泉（青・HP30%とMP25%を回復）、古びた石碑（青・ATK/DEF/SPDのいずれかが+12%、効果はそのダンジョンの間だけ）の4種
- 1ダンジョン＝3〜5回の連戦で、最後は強化された「◯◯の主」とのボス戦。戦闘はタップ不要で自動的に次へ進む。ダンジョン入場時にHP/MPは全快し、道中の戦闘では持ち越されるので、MP配分が攻略要素になる
- 敵を倒すとEXP・装備ドロップを獲得。レア度はN(ノーマル)/R(レア)/SR(スーパーレア)/UR(ウルトラレア)/LR(レジェンドレア)の5段階で、出現比率はおよそ71% / 22% / 6.5% / 0.35% / 0.15%。上位ほど急激に出にくくなり、URは10周ほど周回してようやく出るか出ないか（10周での遭遇率はおよそ15〜25%）、LRは100周に1個出るか出ないかくらいの体感になる。EXPとレベルアップは戦闘ごとに即時反映される
- **ドロップ品はダンジョンを踏破して初めて確定する**。道中で見つけたアイテムは一旦保留され、踏破すれば所持品（インベントリ）に入る（自動分解ONなら対象レア度はその場で強化石に変換）が、**全滅した場合はその周回で見つけたドロップを一切持ち帰れない**（所持品にも入らず、強化石にも変換されない）。全滅時のログには「全滅したため、道中で見つけた◯個のドロップは持ち帰れなかった」と出る。テイムも踏破時のみ。一方EXP・レベルアップは戦闘に勝つたびに即時反映されるため、全滅しても勝った戦闘ぶんのEXPは残る（放置ゲームとしてのストレスを抑えるための仕様）。ログには獲得一覧（踏破時のみ）が出る
- モンスターは全200種（ボスを含む通常129種＋レア71種）。ダンジョンは7地方・35か所（ヴェルデ地方 推奨Lv1〜15、サブル地方 推奨Lv17〜30、グラシア地方 推奨Lv32〜45、イグニス地方 推奨Lv47〜60、マリナ地方 推奨Lv62〜75、セレスタ地方 推奨Lv77〜88、アビス地方 推奨Lv90〜100）で、それぞれに6〜7種の雑魚プールと1体の専用ボス、2体のレアモンスターを配置していて、奥のダンジョンほど新しい顔ぶれが増えていく。各モンスターには炎/水/風/土/光/闇/氷など見た目・図鑑用の「属性」タグを付けているが、これは説明文とアイコンの色分けのみに使うフレーバー情報で、戦闘の耐性・弱点計算には一切影響しない
- **地方とレアモンスター**: ダンジョンは地方ごとに分かれ（ヴェルデ・サブル・グラシア・イグニス・マリナ・セレスタ・アビスの7地方35か所、推奨Lv100まで）、マップは地方ごとに切り替えて表示する（地方が2つ以上になると上に切り替えが出る）。各ダンジョンには2〜3体の**レアモンスター（★）**がいて、ボス戦以外の戦闘で4%の確率で敵1体と入れ替わって現れる。能力値は1.3倍・EXPは5倍で、倒すとスーパーレア以上の装備を必ず1個落とす。書物のモンスター辞典ではダンジョンごとに★レアの印が付く
- **装備のレベル**: 装備は拾ったダンジョンの推奨Lvを「装備のレベル」として持ち、能力値は1Lvごとに基礎値の+12%伸びる（奥のダンジョンの装備ほど強い）。名前の後ろに「Lv.◯」と表示する（Lv.1は省略）
- 探索画面右上の「自動分解」をONにすると、対象レア度のドロップは所持品に入らずその場で強化石（装備強化の素材）に変換される。ONにすると「対象:」のレア度フィルター（チップの表記はN/R/SR/UR/LR、個別にON/OFF可能、既定はN・Rのみ）が現れ、周回中に残しておきたいレア度は外しておける。強化石・自動分解のON/OFF・フィルターの設定はすべて端末に保存され、次回起動時も引き継がれる。設定は全チーム共通で、出撃した瞬間（自動周回では各周の出発時）の設定がその周回に適用される。どこかのチームが探索中・自動周回中の間は、周回の途中で設定が変わらないようボタンとフィルターが押せなくなり、「探索中は変更できません」と表示される
- 装備はそれぞれ個別に+0〜+99の強化値を持つ。キャラ詳細画面で枠を開き「強化する」から挑戦でき、成功するとステータス上昇量が伸びる（+が高いほど、また上位レア度ほど1回あたりの伸びが大きい）。強化石は失敗しても消費され、成功率はレア度が高いほど低く、かつ+が上がるほど指数的に下がっていく（下限3%。レジェンドレアのみ下限0.5%）。ノーマル装備は+99でも半分近い成功率が残るが、レジェンドレアは早々に成功率が沈み込み、さらに+が上がるほど1回あたりの消費強化石も増える（+0で150個→+98で500個）。+98→+99は成功率0.5%×500個で、期待値として強化石約10万個を要する。**天井**があり、今の+値で失敗に使った強化石がその段の期待消費の1.5倍に達すると次の強化は必ず成功する（強化画面に「天井 ◯ / ◯」と表示、成功するとリセット）。成功率100%で強化できる有償の「確定強化石」（1個＝強化石1万個ぶんとして、その段の期待消費に応じて必要個数が増える。LR+98→+99は10個）は機能フラグ（`guaranteedStone`）ONで無料テストショップから受け取れる。実決済は未実装（現行商品は`docs/production-plan.md` §5.7、本番案は`docs/monetization-design.md`）
- **装備の枠**: 右手・左手・頭・体・装飾品1〜3の7枠。装飾品は最初1枠で、各ジョブの固有ツリーの「装備の心得」（3SP）「装備の極意」（5SP）で1枠ずつ増える（最大3枠。ツリーはジョブごとなので、転職すると枠数も変わる）。スキルツリーを持たないモンスターはLv20・Lv40で増える。キャラ詳細の装備タブで枠をタップすると、そのキャラが付けられる所持品だけが候補に出る
- **装備の種類と装備制限**: 装備は26種類（武器12: 剣・大剣・短剣・斧・槍・刀・弓・かぎ爪・大鎌・メイス・杖・両手杖／盾2: 小盾・大盾／頭3: かぶと・ぼうし・ずきん／体3: よろい・軽よろい・ローブ／装飾品6: お守り・指輪・くつ・腕輪・耳飾り・ブローチ）。種類ごとに上がる能力値が決まっていて、複数の能力値が上がる種類もある。ジョブごとに持てる種類が決まっており（`js/data.js` の `JOB_EQUIP`。装飾品はだれでも付けられる）、大剣・槍・弓・大鎌・両手杖は**両手武器**（強いが左手が使えない）。とうぞく・にんじゃ・ぶとうか・けんせい・けんごうは**二刀流**で、左手にも片手武器を持てる。転職して持てなくなった装備は所持品に戻る

- **下のナビ・仲間の切り替え**: 下のナビ（編成・探索・書物・設定）はタイトル以外の全画面に出る。キャラ詳細の「‹」「›」で、開いているタブのまま前後の仲間に切り替えられる（パーティの順、その後に控え）
- **編成メニュー**: 下のナビの「編成」で開くメニュー。ギルド（仲間を呼ぶ・パーティ編成・仲間と別れる）、鍛冶屋（装備強化・装備分解・所持品確認）、ショップ（課金アイテム）に分かれている。「仲間と別れる」は、パーティに編成していない・お気に入りでない仲間を選んで別れる（装備は所持品に戻る。2回押しで確定、最低1人は残す）。「装備強化」は装備中・所持品の装備を一覧から選んで強化できる（探索中のチームのキャラの装備は除く）
- **ショップ（課金要素）**: 編成メニュー・設定画面から開く。本番では課金で買う予定の商品を、プロトタイプでは購入ボタン（2回押し）で無料で受け取れる（価格は仮表示）。自動周回x100（買い切り。業火の霊峰を踏破すると購入できる）・戦闘速度x3/x5（買い切り。速度ボタンは持っている速さだけを x1→x2→x3→x5 の順に切り替え、x5はx3が無くても使える）、確定強化石（1個／10＋1個。強化画面で使え、足りない時はショップへの導線が出る）、仲間のBOX＋50（何回でも、最大1000人）。仲間のBOXは最初50人までで、満員の間は「仲間を探す」ができず、テイムの抽選もしない（上限を超えて持っている仲間は減らさない）。購入の記録はセーブに保存される（商品と方針は `docs/production-plan.md` §5.7）
- **個体値**: テイムしたモンスターは、能力値ごとに0.9〜1.1倍の個体差がテイムした時に決まる（平均は今までと同じ）。キャラ詳細に評価（個体S〜D）と、高い能力値に▲・低い能力値に▼を表示する。同じ種族を合成すると、素材の方が高い能力値が少しずつ上がる（上限1.1倍）。以前からいるモンスターは標準（1.0倍）のまま
- **モンスター合成**: テイムしたモンスターのキャラ詳細画面には、人間の「ジョブ」タブの代わりに「合成」タブがある。控え（どのチームにも編成していない）モンスターを合成素材として選ぶと、その子たちは消滅し（装備していたアイテムは所持品に戻る）、素材1体あたり「種族ごとの基本EXP（その種族が出る一番早いダンジョンのLvで1レベル上げるのに必要なEXP。テイム直後のLv1でも入る）＋素材が積み上げてきたEXPの半分」が対象のモンスターに経験値として還元される（合成先と同じ種族の素材は1.5倍）（レベルアップ・技の習得もその場で反映）。チームに編成中のモンスターとお気に入り（★）のモンスターは誤って消費しないよう素材候補から除外される。「まとめて選ぶ」で、候補をすべて・種族ごとにまとめて選べる。素材の消滅は取り消せないため、合成ボタンは2回押し（「本当に◯体を合成する（取り消せません）」）で確定する。同じ種族の重複個体を育て直す手間を省き、量産されがちな低レア・下位モンスターの使い道を作る機能
- **冒険者の書（書物）**: 探索画面の下の「書物」から開く本の形の画面。目次から各項目へ進み、「もどる」で1つ前のページに戻る（目次からは探索画面へ）
  - **冒険の手引き**: ゲームについて・パーティと編成・種族とジョブ・スキル・装備と強化・探索と自動周回・自動分解・離れている間の進行・データの保存の説明（`js/ui/book.js` の `BOOK_GUIDE`）
  - **モンスター辞典**: 「すべてのモンスター」（これまでに遭遇した全モンスター。未遭遇は「？？？」）と「ダンジョン一覧」。ダンジョンを選ぶと、そのダンジョンの魔物（雑魚とボス）のうち**そのダンジョンで出会ったもの**だけが表示される（記録を始める前に別のダンジョンで出会った敵は、そのダンジョンで出会い直すと載る）。まだ行けないダンジョンは「？？？」。カードをタップするとアイコン・属性・テイム可否・説明文・HP/ATK/DEF/SPD/EXPのモーダルが開く
  - **アイテム辞典**: シリーズ一覧から開き、各シリーズの26種類×レア度5段階のうち、これまでに手に入れたもの（とセット効果）。下の「名のある装備」から地方ごとに開くと、手に入れた名のある装備の効果と説明文が読める（踏破して持ち帰った物。自動分解した物も含む）。記録を始める前のセーブでも、いま持っている装備（所持品・装備中）は載る
  - **種族辞典・ジョブ辞典**: 種族の説明・能力値の傾向・種族特性、ジョブの説明・能力値の傾向・アビリティ・転職の条件。なかまの人数・経験者の人数も出る
  - **冒険の記録**: ダンジョンに潜った履歴（日時・パーティ・ダンジョン・踏破／全滅した戦闘・EXP・アイテム・自動分解・テイム）。新しい順に最大50件。離れている間の自動周回はまとめて1件
  - 記録（ダンジョン別に出会った敵・手に入れた装備・潜った履歴）はメインセーブに入るので、クラウドセーブにも残る（`js/model/records.js`）。全体の遭遇の記録（すべてのモンスター）は従来どおり端末の別キー
- アビリティはキャラクターのレベルに応じて習得数が増える（各ジョブLv.1/5/10/15で1個ずつ、計4個）。レベルアップ時に習得するとログに表示され、未習得の技はパーティ編成画面に「Lv.◯で習得」とグレー表示される
- 探索画面には再生速度(x1/x2)切り替えがあり、放置ゲーム感覚で周回できる
- 道中で全滅するとそのダンジョンは失敗。HPは自動で回復し、「再出撃」で同じダンジョンに再挑戦するか「マップ」で別のダンジョンへ移動する

## 確認用モード（後半のダンジョンを先に確かめる）

設定画面の「開発者用」を押して合言葉を入れると、確認用モードで開き直し、そのままコンプリート（すべてを終えた状態）になる（開発者用）。入ったことは端末が覚えるので、ホーム画面のアイコンから起動しても確認用モードのまま。設定画面の「ふつうのモードに戻る」で抜ける。画面の左上に「確認用モード」と表示される。

URLの最後に `?debug` を付けて開いても（例: `https://nova-xx-zz.github.io/ios-hackslash-prototype/?debug`）合言葉を聞かれ、合っていれば確認用モードになる（この時はコンプリートにはしない）。

- 合言葉はコードに書かず、SHA-256のハッシュだけを `js/debug-gate.js` に持つ（合言葉は開発者だけが知っている）。一度入れた端末は覚えるので、2回目からは聞かれない。大文字・小文字、全角・半角、「ー」と「-」の違いは区別しない。間違えたら3回まで入れ直せる。違う合言葉では入れない。テストプレイヤーがうっかり入るのを防ぐための簡単な守りで、強い守りではない
- **別アイコン（任意）**: Safariで `https://nova-xx-zz.github.io/ios-hackslash-prototype/admin.html` を開き、共有 →「ホーム画面に追加」で、ふつうのアイコンとは別の「開発用」アイコンも作れる。アイコンから起動すると `index.html?debug` を開く（`admin.html`・`admin.webmanifest`）。ホーム画面のアイコンはSafariや他のアイコンと保存場所が別なので、初回は合言葉をもう一度聞かれ、データも別になる。ふつうのアイコンのまま設定画面の「開発者用」から入ってもよい
- 合言葉を変える時は `node -e 'console.log(require("crypto").createHash("sha256").update("新しい合言葉").digest("hex"))'` の結果を `PASS_HASH` に入れる

- 保存場所は本番と別（キーの頭に `qpdebug:`）で、クラウドセーブも使わない。ここで遊んだ内容は、ふだんのセーブやクラウドのバックアップには残らない
- 設定画面の「確認用モード」の欄から、各地方の入口（または最後のダンジョンの手前）まで一気に進められる。押したダンジョンより前をすべて踏破済みにし、第一のパーティの全員をそのダンジョンの推奨Lvにして、適正装備（難易度の基準と同じレア度・+値・装備のレベル）を付け、スキルツリーのSPを基準と同じ「素直な振り方」で振る（`js/ui/debug.js`）
- **コンプリート**（2回押し）: すべてを終えた状態にする。全35ダンジョンを全モード踏破、第一〜第四のパーティ（20人）をLv上限・アビスシリーズのLR+99・スキルツリー全振り・全ジョブLv99に、テイムできる37種を1体ずつ（Lv100・個体値最大・LR+99）、図鑑・アイテム辞典を全部、ショップの買い切りを全部・仲間のBOX最大・強化石と確定強化石を大量に。確認用の仲間・所持品は置き換わる
- 「確認用のデータを最初からにする」（2回押し）で、確認用の保存場所だけを消して最初からにできる
- 「ふつうのモードに戻る（この端末の合言葉も忘れる）」で、ふつうのモードに戻り、この端末に覚えた合言葉も消す（次に入る時はまた聞かれる）

## iPhoneのホーム画面に追加して遊ぶ（PWA）

iPhoneのSafariでページを開き、共有ボタン →「ホーム画面に追加」を選ぶと、アイコンから全画面のアプリのように起動できる。

- 一度オンラインで開いたあとは、機内モードなどオフラインでも起動して遊べる（`sw.js`。オンラインの時は常に最新のファイルを使う）
- **ホーム画面から起動したアプリと、Safariで開いたページは、セーブデータが別々になる**（iOSの仕様）。Safariで遊んだ進行はホーム画面のアプリには引き継がれない
- ステータスバーは不透明の黒（`apple-mobile-web-app-status-bar-style: black`）。ページをステータスバーの下まで描く `black-translucent` にすると、ホーム画面から起動した時にiOSが表示の高さをステータスバーぶん短く計算し、画面の下が切れる
- 画面の上下左右は、iPhoneの機種ごとのノッチ・Dynamic Island・ステータスバー・ホームバーを避けて配置する（`css/style.css` の `--safe-top` などの変数。値はOSから受け取る）。探索画面のログ欄の下端は、下のドックの実際の高さを測って合わせる（`js/ui/dock.js` の `syncDockOffset`）
- ホーム画面に追加したアプリのデータは、Safariで7日間開かなかった時の自動削除の対象にならない（iOSの仕様。ただしアプリを削除するとデータも消える）

## iOSアプリ化（Capacitor）

`ios/` は Capacitor で生成した Xcode プロジェクト（アプリID `com.nova.swordcrest`、表示名「ソードクレスト」、縦向きのみ、Swift Package Manager 使用で CocoaPods は不要）。ゲーム本体はビルド不要のままで、アプリに入れる時だけ `www/` にコピーする。

```
npm install          # 初回のみ（Capacitor を入れる。ゲームの実行・テストには不要）
npm run cap:sync     # www/ を作り直して ios/ に反映する（ゲームのファイルを変えたら毎回）
npm run cap:open:ios # Xcode で開く（Mac のみ）
```

- `www/` と `ios/App/App/public/` は自動生成なので Git には入れない（`.gitignore`）
- ビルドと実機・TestFlight への配信には Mac と Xcode（またはクラウドの Mac）、Apple Developer Program への登録が必要
- アプリアイコンは `icons/icon-1024.png`、起動画面は `icons/splash-2732.png`（透明なし）を `ios/App/App/Assets.xcassets/` にコピーしている
- Service Worker（`sw.js`）はアプリ内では動かない（`js/pwa.js` が https 以外では登録しない）。アプリにはファイルが最初から入っているので、オフライン対応は不要

## クラウドセーブ（Firebase）

進行は Firebase（プロジェクト `sword-crest-jp`）に自動でバックアップする。プレイヤーの操作は不要で、起動すると匿名ログイン（Firebase Authentication）し、セーブデータを Firestore（東京リージョン）の `saves/{ユーザーID}` に置く。

- 送るタイミング: セーブのたびに最大1分おき、アプリを離れる時（画面が隠れた時）はすぐ。オフラインの間は送らず、つながったら送り直す
- 設定画面の「クラウドセーブ」から、状態の確認・「今すぐバックアップ」・「クラウドから復元」ができる。復元は2回押しで、内容（日時・なかまの数・最高Lv・踏破数・強化石）を見せ、端末のほうが新しい時は警告する。復元したセーブの自動周回は止めた状態にする（古いセーブを戻すたびにオフライン報酬が入るのを防ぐ）
- 匿名ログインは端末ごとなので、**別の端末への引き継ぎはまだできない**（今後 Apple / Google アカウントとの連携で対応予定）。ホーム画面のアプリとSafariも別のユーザーになる
- セキュリティルール（Firebase コンソールの Firestore →「ルール」）で、ログインした本人の `saves/{uid}` だけを読み書きできるようにしている:
  ```
  match /saves/{uid} {
    allow read, write: if request.auth != null && request.auth.uid == uid;
  }
  ```
- `js/firebase-config.js` の apiKey などは公開して問題ない値（アクセスの制限はセキュリティルールで行う）
- Firebase の SDK は CDN から読まずに `js/vendor/firebase.js` に同梱している（使う関数だけを esbuild でまとめたもの。ゲームの起動を遅らせないよう、起動の1.5秒後に読み込む）。SDK を更新する時は `package.json` の firebase のバージョンを変えて `npm install && npm run build:firebase`（使う関数を増やす時は `tools/firebase-entry.js` に足す）

- `js/ui/` — 画面の処理（元は1つの game.js だったものを画面ごとに分けたもの。`index.html` の読み込み順のまま、トップレベルの関数・変数を共有する）

## オート戦闘AIのロジック（現状）

- ON状態かつレベルで習得済みのアビリティのうち、MPが足りるものを候補にする
- 回復技は「誰かのHPが減っている時だけ」候補に入れる（無駄撃ちしない）
- まず「アビリティ優先度」が最も高い技のグループに絞り込み、その中で**今の敵・味方の状況に対する期待効果**が最も大きい技を使う。期待効果は、実際のダメージ計算式（敵の防御・多段技は1回ごとに防御で減る・会心の期待値）で見積もった与ダメージ、回復技なら回復量で、敵の残りHPや味方の減ったHPを超える分は数えない。優先度「通常」のグループでは通常攻撃とも比べ、MPを使う技が通常攻撃より弱ければ通常攻撃にする。期待効果が同じなら消費MPが少ない方を選ぶ（以前は「要求レベルが高い技ほど強い」前提で選んでいたため、後から覚える技が弱い場合に弱い技を使い続けていた）
- **アビリティ優先度**: キャラ詳細画面で技ごとに「優先／通常／温存」を設定できる（タップで循環）。優先度が同じ技どうしは期待効果で選ばれるので、何も設定しなければ「その場で一番効く技」を使う。「優先」にした技は効果に関係なく最優先で使い、「温存」にした技は他に使える技が無い時だけ使う
- **攻撃対象の優先度**: 単体攻撃・通常攻撃が狙う敵をキャラごとに「弱い敵から（既定）／強い敵から／ランダム」で設定できる。回復は引き続き残HP割合が一番低い味方を自動選択

## 現状の設計方針（プロトタイプ版）

- 戦闘はDOMベース（Canvasは使わず、テキストログ＋カード主体のUI）。敵のグラフィック表示は持たず、残り状況はログカードの見出しにテキストで出す
- チームはI〜IVの4枠があり、全チームが常時並行して探索できる。表示中チーム以外はUIを描画しないだけで、内部のATB進行自体は同じフレームで一緒に進む
- ジョブは基本職6種＋上級職6種の計12種、各ジョブにアビリティ4種（Lv.1/5/10/15で習得）。状態異常やバフ系の仕組みがないため、技は「ダメージ / 回復 / 吸収」の組み合わせで差別化している
- 装備は3スロット。所持品は全チーム共有で、装備中のアイテムは所持品から外れるので取り合いになる（上限なし・売却や分解は未実装）
- 見た目はプレースホルダー。システムの面白さの検証が目的

## 今後の検討事項

- 状態異常やバフ/デバフの仕組み（現状は技がダメージ・回復・吸収のみなので、盾役や補助役のジョブが作れない）
- AIの条件をさらに細かくするか（例: 「HPが◯%以下の時だけ温存技を解禁」のような条件付き優先度。現状は常時固定の3段階）
- 所持品の整理（並べ替え、上限）と装備の比較表示
- 強化石の使い道を装備強化以外にも広げるか（現状は+強化のみ）
- テイムできるモンスターの種類を増やすか（現状はスライム/ゴブリン/コウモリ/ウルフの4種）
- 上級職をさらに増やすか、また上級職どうしを掛け合わせるような発展形（現状は基本職1つにつき上級職1つのみ）
- ダンジョンの数と分岐を増やすか（現状は5つの一本道。分岐ルートを作ればビルドの選択も活きる）
- 控えキャラを自由なグループに仕分ける機能（所持数が増えたら必要。現状は「控え」1つにまとめている）
- 道中イベントをさらに増やすか（現状は宝箱/罠/泉/石碑の4種。行商人・分かれ道など、選択が絡むものはオート進行と相性を要検討）
- 期間限定イベント（レアドロップ率アップ、期間限定の出現モンスターと専用ドロップなど）。サーバーを持たないため「今このイベントが有効か」は端末のローカル日時と`data.js`に定義した開始/終了日で判定するしかなく、イベントの追加・終了のたびに`data.js`を編集してコミットし直す運用になる見込み
- ストーリー要素の追加（現状はマップ→連戦のみ）
- 見た目・演出（スプライト、エフェクト、SE/BGM）の作り込み
- iOS ネイティブ化する場合の技術選定（Capacitor でラップ / Swift・Unity・Godotで書き直し 等）
