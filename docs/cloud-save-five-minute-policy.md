# プロトタイプのローカルセーブ／クラウド同期（2026-10-22）

## 保存タイミング

| 対象 | タイミング | 備考 |
| --- | --- | --- |
| ローカル（`jobquest_save_v1`） | ダンジョン完了・各操作で呼ばれる`saveGame`、20秒間隔、画面非表示時 | 既存のセーブ形式・キー・復元処理は変更しない |
| クラウド（`saves/{uid}`） | **最短5分に1回**、未同期のデータがある場合 | 同期済み内容と`savedAt`以外同じなら送らない |
| 自動周回中 | 進行データが同じでも5分間隔で更新 | `savedAt`がオフライン精算の起点になるため |
| 画面非表示・手動バックアップ | 未同期データを可能なら即時送信 | ブラウザ・iOS側が通信完了を保証しない |
| 通信失敗 | 最低60秒の待機後に最新の保留セーブを再試行 | ローカルセーブを消さず、次回成功まで保留。オンライン復帰時は即時再試行 |

初回は未同期セーブがあればすぐ送信する。ゲーム進行時に定期ローカル保存の`qp:saved`通知を受けても、クラウド送信を毎回は行わない。

## 制約と将来移行

- 現行方式は**プロトタイプ専用**の匿名Firebase認証＋Firestore直接保存。Googleアカウント横断復元、2端末競合・課金権利の正本管理、7日分の世代履歴は提供しない。
- `js/core/cloud-large-backup.js`は実ネットワーク未接続。容量制限を超えたデータのクラウド同期は行わず、設定画面の保存診断で確認する。
- バックアップ直後の通信断で最大5分程度のクラウド未反映期間が生じうる。強制終了やOSによるバックグラウンド停止時の送信は保証されない。
- 正式版の`swordcrest`では`docs/architecture/認証・セーブ・データ引継ぎ設計.md`に従い、Google認証付きサーバー側API、revision CAS、購入権利を別正本とする方式へ移行する。
- 本変更は既存プレイヤーのセーブJSON、ローカルのキー名、復元時のプレイデータを変更しない。

## 確認事項

`node --test tests/cloud-save-interval.test.js`と`npm test`で、5分間隔、保存時刻のみの更新、自動周回中の同期、再送、非表示時の即時送信、送信中の更新を確認する。実機ではSafari／Chromeで通信断・復帰・バックグラウンド化を別途検証する。
