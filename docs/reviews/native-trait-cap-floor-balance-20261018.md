# 通常戦闘の特性持ち最大3体・階層別比較（2026-10-18）

## 変更範囲（試験のみ）
- PR #116 の試験ブランチから派生。**通常版・本番・既存セーブは変更しない**。隔離された実戦闘測定でのみ `capPilotNativeTraits` を渡す。
- 1戦闘の敵総数は1〜5体。通常戦闘では生来の特性持ち・試験追加の特性持ちを**合計最大3体**にする。
- 既存特性4〜5体の過密パックが選ばれた場合、**敵のインスタンス生成より前**に、同一ダンジョンの非特性通常敵候補へ超過分のみ再抽選する。元の種族の耐性を後から取り消す処理は行わない。
- **レア敵・ボスは保護**。レア敵の種族・レア扱いは変えない。ボス戦は試験追加・再抽選とも行わず、ボスのHP60%フェーズも維持。
- 置換できる通常敵が存在しないプールでは明示的にエラー（silent fallbackは設けない）。後半ダンジョンへの導入前に候補プールの整備が必要。
- 3F/5FにはNormalの耐性倍率のみ使用。0倍の完全無効は導入しない。Hard/Extra/10F/15Fは別受入が必要。

## UT / IT
- `node --test tests/random-trait-encounters.test.js`: 同一seed再現、敵数1〜5、既存＋追加特性<=3、レア/ボス保護、0倍無効なし、既存テンプレート無変更、全滅時報酬全ロスト。
- `node tools/random-trait-density-study.js --floor-compare --trials=100`: 草原3F・森3F・洞窟5Fを標準初期PTで各100周、通常 vs 1〜3体でクリア率・ゲーム内秒・持ち帰りアイテム・強化石・特性人数を比較。
- `node tools/random-trait-density-study.js --trials=100`: 洞窟5Fの5PT×通常/特性、各100周。特性版でnative込み4〜5体が1件でも生じたら測定失敗とする。
- CI: `.github/workflows/random-trait-density-study.yml`。上記の各試験が成功し、レポートを確認するまでDraft扱い。
- 100周単位の数%の差は統計的に確定とみなさない。追加抽選により同じseedでも後続乱数列が変化するので厳密な一戦一戦のペア比較ではない。

## セルフRV観点
1. 変更は純粋な試験補助関数・試験注入フックのみ。本番通常ゲームはフックを渡さない。
2. 種族の元特性・報酬用key・レア/ボス/中ボスへの意味変更はない。**超過パックのみ種族を再抽選するため、該当戦闘のEXPやテイム候補は変わり得る**。公開採用前に経済テストで再測定する。
3. ランダム特性を付ける場合は元の生来の特性持ちも上限・1〜3体の目標に数える。
4. レア敵は保護するが、ボス戦の取り巻きへの本方針適用は未決（現在の試験ではボス戦全体を除外）。
5. 同一seed、旧セーブ維持、ロスト0漏洩、既存確率・課金台帳への影響なしを確認する。
