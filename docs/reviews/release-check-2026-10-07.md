## 総評

- **課金がまだ仮の実装**であること

ゲーム内では、次の2つが実際に起こり得る不具合として優先度が高い。

- 実際のプレイの戦闘に時間切れがない
- 2回押しの確認がダブルタップ1回で通ってしまう

## RC-01 課金が仮の実装（高）

**現状**

- ショップ（`js/ui/shop.js`・`js/model/shop.js`）は、「購入する」を2回押すと無料で受け取れるテスト用の作り。
- 購入した記録（`S.purchases`）と有償の確定強化石（`S.guaranteedStones.paid`）は、端末のセーブ（localStorage）とクラウドのバックアップにあるだけ。セーブを書き換えれば、買い切りも有償の石も手に入る。

**影響**

- 有償の商品がただで手に入る。
- 有償の通貨を売る場合は、資金決済法への対応も必要になる（[本番化・課金方針](../production-plan.md)§6）。

**修正内容**

1. iOS版は Apple のアプリ内課金（StoreKit）で買えるようにする。
   - Capacitor のアプリ内課金プラグインを使う。
   - 買い切り（自動周回x100・速度x3/x5・仲間のBOX）は「非消耗型」、確定強化石は「消耗型」として登録する。
2. 購入の確定は、Apple のレシート（トランザクション）をサーバーで確かめてから行う。
   - サーバーは Firebase Cloud Functions を想定。
   - 購入記録は、プレイヤーが書き換えられない場所（Firestore の別コレクションを Functions だけが書く）に置く。
   - 端末の `S.purchases` はその写しとして扱う。
3. 「購入を復元」ボタンを付ける（Apple の審査で必須）。
4. 有償の確定強化石を売る場合は、資金決済法（前払式支払手段）の届出が必要かを確認する。
   - 必要なら、有償分の残高の管理と、未使用残高の上限管理を入れる。
5. それまでのテスト版では、今の「無料で受け取る」のままでよい。ただし本番ビルドでは無料の受け取りを機能フラグで止める。

## RC-02 「開発者用」ボタンが本番にも出る（高）

**現状**

- 設定画面の「開発者用」（`js/ui/debug.js`）と URL の `?debug` は、合言葉を入れると確認用モードになる。
- 合言葉は SHA-256 のハッシュだけを `js/debug-gate.js` に持っているが、ハッシュ自体は公開されている。合言葉が短いので、総当たりで当てられる。
- 確認用モードは保存場所が別でクラウドも使わないので、ふだんのセーブは書き換わらない。ただ、「コンプリート」で全部そろった状態を見られてしまう。

**修正内容**

1. 本番用の機能フラグ（例: `FEATURE_FLAGS.devTools`）を作る。OFF の時は次のようにする。
   - 「開発者用」ボタンを出さない。
   - `?debug` の合言葉も聞かない（`isDebugMode()` を常に false にする）。
2. テスト版（GitHub Pages）は ON、iOS の本番ビルドは OFF にする。ビルドで切り替えられるよう、`npm run build:www` で書き換える。
3. 合言葉を残す場合は、長くて推測しにくいものに変える。

## RC-03 クラウドセーブの守り（高）

**現状**

- Firestore のルールは「ログインした本人の `saves/{uid}` だけ読み書きできる」（README）。データの大きさ・形は確かめていない。
- 匿名ログインは誰でもいくらでも作れる。アプリ以外（スクリプトなど）から接続して、大量のアカウント・大きなデータを書き込める。

**影響**

- 保存容量と書き込み回数の費用がかさむおそれがある。
- 他人のデータは読めないので、情報漏えいの心配は小さい。

**修正内容**

1. **Firebase App Check**（iOS は App Attest、Web は reCAPTCHA Enterprise）を入れる。アプリ以外からの接続を断る。
2. ルールで、書き込めるデータの形と大きさを制限する。

   ```
   match /saves/{uid} {
     allow read: if request.auth != null && request.auth.uid == uid;
     allow write: if request.auth != null && request.auth.uid == uid
       && request.resource.data.keys().hasOnly(["data", "savedAt", "schemaVersion", "chars", "updatedAt"])
       && request.resource.data.data is string
       && request.resource.data.data.size() <= 950000;
   }
   match /{document=**} { allow read, write: if false; }
   ```

3. Firebase（Google Cloud）で、予算アラートと使用量の上限を設定する。

## RC-04 実際のプレイの戦闘に時間切れがない（高）

**現状**

- オフライン精算の戦闘は300秒で打ち切り、負け扱いにしている（`js/model/run.js` の `OFFLINE_BATTLE_MAX_SECONDS`）。
- 一方、画面で進む実際のプレイの戦闘（`js/ui/explore.js` の戦闘ループ）には時間切れがない。

**起き方**

- エクストラでは特性で攻撃が「効かない」ことがある。例: 物理だけのパーティで霊体の敵と戦う。
- 回復のMPが尽きるまで全滅せず、敵の攻撃も最低1ダメージずつなので、何十分も戦闘が続く。
- 自動周回が止まったように見え、オフライン精算とも扱いがずれる。

**修正内容**

1. 実際のプレイの戦闘も、戦闘時間（ゲーム内の秒。倍速なら速く進む）が `OFFLINE_BATTLE_MAX_SECONDS`（300秒）を超えたら打ち切る。
   - 打ち切りは「撤退」とし、全滅と同じ扱いにする（その周の未確定ドロップは失い、自動周回は止まる）。
2. ログに「決着がつかないため撤退した（攻撃が効いていないかもしれません）」と出す。
3. 戦闘の秒数は `battle.time`（戦闘エンジンが進めている時間）で判定する。オフラインと同じ基準になる。
4. テスト: 攻撃が効かない敵との戦闘が、300秒で撤退になること。

## RC-05 2回押しの確認がダブルタップで通ってしまう（高）

**現状**

取り消せない操作は、1回目で「本当に〜する」に変わり、2回目で確定する作り。対象は次の通り。

- 仲間と別れる（`js/ui/menu.js`）
- 装備分解（`js/ui/inventory.js`）
- モンスター合成（`js/ui/detail-tabs.js`）
- ツリーの振り直し・汎用枠の交換（`js/ui/detail-tree.js`）
- ショップの購入（`js/ui/shop.js`）
- クラウドから復元（`js/ui/settings.js`）
- 確認用データの初期化（`js/ui/debug.js`）

確認ボタンは、1回目と同じ位置にすぐ出る。そのうえ `touch-action: manipulation` でダブルタップのズームを止めているので、ダブルタップ1回が2回のクリックになる。

**修正内容**

1. 共通の関数 `confirmReady()`（仮）を作る。確認の状態に入った時刻を覚え、**0.5秒以内の2回目の押下は無視する**。
2. 確認中の表示がわかるようにする（色を赤にする・文言を変える）。これは今もできている。
3. 上の全部の2回押しを、この関数に置き換える。
4. 確認の状態は、別の場所を押したり画面を移ったりしたら解除する。今も一部はそうなっているので、全部そろえる。

## RC-06 仲間の名前を HTML として画面に入れている（中）

**現状**

プレイヤーが付けた仲間の名前を、`innerHTML` の文字列にそのまま入れている箇所がある。

- `js/ui/create.js` のプレビュー（入力中の名前）
- `js/ui/detail-tabs.js` の能力値タブの見出し
- `js/ui/dock.js` の探索画面のカード
- `js/ui/party.js` の編成画面のカード

**起き方**

- 名前に `<b>` などを入れると表示が崩れる（入力は8文字まで）。
- 書き換えたセーブをクラウドから復元すると、文字数の制限を超えた名前も入る。その場合、自分の端末で任意のスクリプトが動く。
- 他のプレイヤーに名前を見せる機能は今はないので、影響は本人の端末だけ。

**修正内容**

1. 文字を HTML として安全にする関数 `escapeHtml()` を共通で用意する。
2. 名前など、プレイヤーが入力した文字（仲間の名前、グループ名、合成のメッセージに入る名前）を `innerHTML` に入れる時は、必ずこれを通す。
   - グループ名はすでに `textContent` で入れているので問題ない。
3. セーブを読み込む時に、名前を文字列・最大文字数（8文字。グループ名は12文字）にそろえる（RC-12 と一緒に）。
4. テスト: `<img src=x onerror=...>` のような名前でも、文字として表示されること。

## RC-08 装備にロックがない／自動分解で大事な装備も消える（中）

**現状**

- 装備にロック（保護）の仕組みがない。手動の分解で、UR・LR、名のある装備、+値の高い装備も選べる。
- 手動の分解では、UR・LR を選ぶと件数の注意が出る（`inventory.js`）。
- 自動分解（`js/ui/dock.js`）は、レア度のチップで UR・LR も ON にできる。ON にしても警告がない。名のある装備やオプション付きの装備も、レア度が合えば落ちた時点で分解される（`js/core/rewards.js` の `settleDrops`）。

**修正内容**

1. 装備に `locked` を持たせる。所持品と強化画面に鍵のボタンを付ける。
   - ロック中は、手動の分解の候補に出さない。
   - ロック中は、自動分解の対象にもしない。
2. 自動分解は、レア度が合っても次のものは分解しない（所持品に残す）。
   - 名のある装備
   - オプション効果が付いた装備（ハード・エクストラ）
3. 自動分解のチップで UR・LR を ON にする時に、確認を出す（「UR・LRも自動で分解されます」）。
4. セーブの形: `item.locked`（真偽値）を足すだけなので、旧セーブの移行は不要。

## RC-09 端末の時計を進めるとオフライン報酬を何度でも受け取れる（中）

**現状**

- オフライン精算は「今の端末の時刻 − 保存した時刻」で離れていた時間を計る（`js/model/run.js`・`js/game.js`）。
- 上限8時間・時計が戻ったら0、までは対策済み。ただ、時計を進めては開く、を繰り返すと何度でも受け取れる。

**影響**

- 自分だけが得をする（ランキングや他人との取引はない）。
- ただ、有償の時短商品（自動周回x100 など）の価値を下げる。

**修正内容（方針の判断が必要）**

- 案A（軽い）: 端末の時計のずれを検出する。
  - クラウドに接続できた時に、Firebase のサーバー時刻と端末の時刻の差を記録する。
  - 差が大きい時（例: 10分以上）は、その分を精算の時間から引く。
- 案B（確実）: 精算の時間をサーバー時刻で決める。
  - 離れる時と戻った時に、サーバー時刻を記録する。
  - オフライン（通信なし）の時は精算しないか、上限を短くする。
- ランキングなどを入れないなら、案A で十分。

## RC-10 2つのタブで同時に開くと進行が巻き戻る（中）

**現状**

- Web版を2つのタブで同時に開くと（Safariとホーム画面のアプリは保存場所が別なので対象外）、両方が同じセーブを読み、それぞれ丸ごと保存する。
- 後から保存した方で、もう片方の進行が消える。
- アイテムが増える方向の問題はない。アプリ版は画面が1つなので起きない。

**修正内容**

1. `BroadcastChannel`（または localStorage の `storage` イベント）で、同じセーブを開いているタブを見つける。
2. 後から開いたタブを「別のタブで遊んでいます」の画面にして、保存を止める（`saveSuspended`）。
3. 「こちらで続ける」を押したら、相手のタブに止まるよう知らせてから、こちらで読み込み直す。

## RC-11 オフライン精算が重くなる可能性（低）

**現状**

- 精算は、離れていた間の周回を実際に戦わせて決める。
- 最大で4チーム×100周（自動周回x100を購入した場合）×1周5戦前後、約2,000戦になる。
- 今回の改善で1戦あたりは軽くなった（Node.js で80戦が約0.13秒）。ただ、実機の Safari では数倍遅いことがある。

**修正内容**

1. iPhone の実機で、4チーム×100周の精算にかかる時間を計測する。
2. 2〜3秒を超える場合は、どちらかの対策を入れる。
   - 精算を少しずつ進めて、画面に「精算中…」を出す。
   - 同じダンジョンの周回は数周ぶんの結果を使い回して見積もる。

## RC-12 セーブの数値の範囲を確認していない（低）

**現状**

セーブを読み込む時（`js/model/save.js` の `deserialize`）、型は確認しているが範囲は見ていない。たとえば次のような値もそのまま読み込める。

- 強化石が数値であれば、マイナスや NaN でも読み込める
- 名前の長さ
- レベルや +値の上限

**影響**

- 書き換えたセーブや壊れたセーブで、画面が崩れたり、計算が NaN になって止まったりする。

**修正内容**

1. 読み込み時に、範囲にそろえる処理を足す。
   - 強化石・確定強化石: 0以上の整数（NaN は0）
   - レベル: 1〜上限
   - +値: 0〜99
   - 名前: 文字列で8文字まで
   - 個体値: 0.9〜1.1
2. テスト: 壊れた値のセーブを読み込んでも、範囲に収まって遊べること。

## RC-14 CSP（読み込める場所の制限）がない（低）

**現状**

`index.html` に Content-Security-Policy がない。今は外部のスクリプトを読まず、Firebase の SDK も同梱しているので、すぐに困ることはない。

**修正内容**

`index.html` に `<meta http-equiv="Content-Security-Policy">` を足す。

- `script-src 'self'`
- `connect-src 'self'` と Firebase のドメイン（`*.googleapis.com` など）

RC-06 の対策と合わせると、もし名前から HTML が入っても、スクリプトは動かなくなる。
