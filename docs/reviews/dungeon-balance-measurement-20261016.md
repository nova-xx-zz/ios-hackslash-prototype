# ダンジョン3F・5F：実データ難易度・報酬バランス検証（96周 × 18条件）

> 測定: 2026-10-16 / 対象: Draft PR #107 / 3F plains・forest、5F cave（ノーマル）
>
> 計測出典: [Dungeon balance trial / Actions #38889118753](https://github.com/nova-xx-zz/ios-hackslash-prototype/actions/runs/38889118753)、[再現用コード](../../tools/dungeon-balance.js)。
> **実戦闘エンジン＋本体オフライン精算シミュレーターの測定値であり、iPhone実機のプレイ時間やユーザー行動ログではない。**
> **本ファイルは数値変更を行わないレビュー記録**。全滅ロスト、ドロップ率、敵能力値は変更しない。

## 検証方法・入力

- 1条件につき96周。固定シード: plains 10531 / forest 20813 / cave 30721。合計18条件×96周＝1,728周。繰り返しで再計算可能。
- 実処理: `Runner.computeOfflineRun`→`createPilotSchedule`→`buildPilotEncounter`→`battleCore.simulate`。入場時に全階層の通常戦闘回数を抽選。レア敵・ボスの報酬、宝箱・鍵付き宝箱・泉も本体関数で処理する。
- 各ダンジョンの推奨Lvを全員に設定（草原Lv1／森Lv4／洞窟Lv7）。初期パーティ: 戦士×2・魔法使い×2・僧侶×1。盗賊入りは戦士1人を盗賊に置換。
- 装備は既存`tools/lib/sim.js`の`standardEquip`を使用し、実`Roster.computeStats`・ジョブ別装備制限・既存ツリー計算で反映。
- **適正装備**: `DUNGEONS[].benchmarkGear`、装備Lvは直前ダンジョンLv、ツリーは`standardTreeRanks`（SP制限内）。
- **強化のみ**: 適正装備からさらに各装備+4。**OP厳選**: 強化のみと同条件で、既存Hardモードの許容上限にあたるOPを各装備に1個セット。**全装備に最適なOPが1個付いている理想的上限寄りケース**であり、実際の入手確率・厳選コストは再現しない。
- **盗賊入り**: Lv7で解錠可能な盗賊にパーティの戦士1人を置換し、通常・オフライン共通の45%スキル発動。`thief-unskilled`は**同じ盗賊編成で解錠術だけ無効**にした比較条件。
- 乱数シードは条件間で一致。ただし戦闘の長さ・ドロップ/解錠の抽選回数で乱数消費がずれるため、**厳密な同一敵・同一戦闘ログのペア比較ではない**。95%区間の精度も1条件96周に限定される。
- `avgSec`は失敗周を含む**1回の試行当たりゲーム内換算秒数（x1）**、`avgClearSec`は踏破した周に限定した秒数。端末の経過秒・オート戦闘高速化倍率は反映しない。
- `confirmedDrops`は**踏破した周の全ドロップ**（未分解）で、`carriedItems`はN装備を自動分解した後に実際の所持品へ残る装備。強化石はN装備を自動分解する設定で計算した1回あたりの受領数。失敗周の持ち帰りは強制的に0。

## 鍵付き宝箱・UR/LR

- 洞窟5Fの盗賊入り：96周で鍵付き宝箱133個を発見、うち解錠対象122回、成功60回（試行回数比 **49.2%**）。失敗/スキル使用不可では報酬なし。
- 同じ洞窟の「解錠なし盗賊」：鍵付き宝箱148個、解錠0回。乱数消費差があるため宝箱の出現個数自体は一致しない。
- 盗賊入りは96周でUR/LR持帰り19個、盗賊入り・解錠無しは7個。ただし高レア度の母数が小さく、**解錠術がUR/LR率を何倍にするという因果推定は不可能**。
- 全18条件・合計1,728周で**攻略失敗からのアイテム持帰りは0**。コード上も `offline.simulateRun` が失敗時に `drops: []` を返し、`applyOfflineRun`が未確定品を確定しない。既存の全ロストルールを変更しない。

## 次の設計提案（まだ採用・実装しない）

1. **洞窟5Fの持久戦の原因を分解**：階層別の戦闘被害・倒れたチーム構成・ボスHP60%前後・残MP・ボス到達率をログ集計。ボス戦以前の全滅かを識別する。
2. **武器強化とOPの評価を同じ敵・行動乱数で測る**：連続seedによる単純な成功率比較だけでなく、敵編成/敵数/イベントを固定した paired-seed 検証に拡張。装備強化が改善に結びつくか確認。
3. **ドロップ経済を「1回あたり」でなく「持帰り/ゲーム内10分」「初期→装備整備までの試行数」で評価**。UR/LRや強化石の供給量も再校正する。報酬が多すぎる場合でも**失敗時全ロストを緩和しない**。
4. 洞窟で適正装備+ツリーが60.4%と低いことが再確認できたら、道中敵の単体ATK・集団構成、回復役の戦闘間のMP維持、5FボスのHP/DEF倍率などを**別ブランチで段階調整**。目安は推奨Lvで安定周回可能な85%以上（旧難易度基準との整合）。
5. 10F・15Fの本体有効化は、この持久戦・報酬供給の校正とSafari/Chrome実機テストが済んでから。

**結論：新仕様は検証継続可能。ただし洞窟5Fは難易度調整、序盤3Fは装備/石供給の再評価が必要。全ロスト・中ボス途中確定なしというゲームの核は一切変更しない。**
