# 剣士スキルパネル六角形UI試作設計

## 目的・適用範囲
- FF12のライセンスボードにある「埋めていく達成感」と、DQ11の六角形パネルの一覧性を、ソードクレスト向けに試す。
- **プロトタイプ版のみ**の比較試作。初期表示は既存の紋章盤。
- 対象は **剣士（job: warrior）の固有ツリー「剛勇の心得」** のみ。汎用Ⅰ〜Ⅲ・剣豪・その他の職業は既存UIを維持。
- main への導入・正式版への移管は、実画面での確認後に改めて判断する。

## 画面・操作
- 既存の固有/汎用タブ、SP、振り直し、キャラ送り、下部詳細ドック、下部ナビは維持。
- 固有ツリーの盤面右上に「紋章盤 / 六角パネル」の切替を設置。既定は紋章盤。表示モードは一時的なUI状態で、セーブデータには追加しない。
- 六角パネルは既存17ノードを七段の蜂の巣型配置で一覧表示。個々のアイコンは既存の剣士紋章SVGを再利用し、名前は選択後の下部詳細に表示。
- 状態色は習得済＝金、習得可能＝青、未解放＝灰、二択封印＝赤。選択中パネルと、その前提パネルを強調。
- 盤面全体を初期表示。既存の拡大・縮小・全体表示、iPhoneのピンチ・ドラッグ、マウスホイールを再利用。
- ノードをタップすると詳細を選択するだけで、誤タップによる即時習得はしない。習得は下部詳細の既存ボタンから行う。

## データ・ルール
- js/data.js の EXCLUSIVE_TREES.warrior が唯一の正本。ノードID、前提、排他グループ、効果、スキルポイント、必要Lv、保存形式は変更しない。
- 表示の位置と実際の習得条件は別物。**六角パネルが隣接しているだけでは解放されない**。判定は必ず canAcquireNode()、習得は既存の treeAcquireWithChoiceConfirm() → acquireNode() を使用する。
- 二択の組番号と封印判定は既存の treeChoiceInfo() に従う。
- 将来パネルが追加され、表示座標が未定義のノードがあれば欠落描画せず従来紋章盤にフォールバックする。

## 実装箇所
- js/ui/detail-tree.js: 紋章盤と六角パネルの切替と描画分岐。
- js/ui/skill-panel-board.js: 六角座標・パネルUIの組み立て（スキル習得ロジックは持たない）。
- css/skill-panel-board.css: 六角パネルだけのスコープ付き装飾。
- index.html: 読み込み順とキャッシュ番号。
- tests/warrior-skill-panel-board.test.js: 切替、17ノード、状態、非対象職、データ不変性。

## 検証・今後の判断
- ローカルNodeテスト: npm test、個別テスト: node --test tests/warrior-skill-panel-board.test.js。
- 画面確認: 393×852、375×812、320×568相当で、上部SP・切替・盤面・下部詳細/習得ボタン・共通ナビが重ならないことを確認する。
- 二択の比較表示、Lv不足の表示、SP不足、習得、振り直し、キャラ送り、ピンチ/ドラッグ、タップ抑止を確認する。
- 全体フィット時のパネルが小さすぎる場合は、最低タップ領域とズーム初期値を再検討する。
- 本試作は**既存の前提グラフを六角格子に変換するものではない**。本採用時に隣接ルールへ変更するなら、それは別PRでゲーム仕様として設計する。
