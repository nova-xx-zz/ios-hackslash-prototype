# 武器・装備強化 UI：目標値ステッパーと天井連動強化

更新：2026-10-23  
対象：プロトタイプ版 `ios-hackslash-prototype`

## 目的

「強化する」を何度も押さず、目標値を `− 10 ＋` のように設定して一度の操作で目標まで連続強化できるようにする。
**天井分を先払いしたり、500個を固定消費したりしない。** 成功率に従い、実際の抽選に必要だった通常強化石だけを都度消費する。

## UI

- 既存の装備情報・現在の強化値・次の成功率・1回分の必要強化石・天井ゲージは維持する。
- メイン操作は `− | +10 | ＋` と `+10まで強化する`。初期目標は+10。現在値が+10以上なら初期目標を現在+1（最大+99）にする。
- マイナス/プラスは1ずつ。選べる範囲は**現在の強化値+1 ～ +99**。上限・下限ボタンは無効化。
- 数値入力フィールド、プリセット、固定500個上限の入力欄は削除する。
- 実行前に2段階確認（意図しない大量消費を防止）。確認途中で目標を変更した場合は最初から確認する。
- 目標までの**「天井まで連続失敗した場合の最大必要強化石」** と、現在の所持強化石を表示。
- 最大必要数は**予測の表示**であり、事前引き落とし・予約はしない。石が足りなくても次の抽選1回分があれば挑戦可能。次の抽選に足りなくなったら途中停止。
- 結果として「目標到達／石不足で中断／異常停止」、開始・終了強化値、挑戦回数、成功・失敗数、**実際に使った強化石**、残数を表示。
- 従来の「1回だけ強化する」操作も二次アクションとして残す。確定強化石を使う既存操作は別のまま。

## 強化ロジック

`Inventory.enhanceToTarget(item, targetPlus)`

1. 有効な目標値かつ所持中・非探索ロック中の装備であることを検証。
2. 現在の装備+値を参照して1回分のコストを算出。
3. 所持通常強化石が1回分に不足すれば停止。現金・確定強化石にフォールバックしない。
4. 既存の `Inventory.enhanceItem` を1回実行する。成功率・失敗・天井ゲージ・使用石数は従来と完全一致する。
5. 成功したら+値を1段上げ、天井ゲージを初期化したうえで**次の強化段階のレート／天井値／必要石を再計算**する。
6. 失敗なら同じ段階で再抽選。ただし次回分の石不足なら停止。
7. 目標に到達すると即座に停止。**天井に達する前に成功した場合、それ以降の天井用石は消費しない。**

現状のデータ保存方式を変更する必要はない。処理後は1回 `saveGame()` を行う。

### 天井までの最大必要石数

`Inventory.estimateEnhanceToTarget(item, targetPlus)`

各段階 `p` での1回コスト `c(p)`、天井到達ライン `t(p)`、その段の既存ゲージ `g(p)` を取得する。
最悪の場合に天井に到達するまで失敗する回数は `max(0, ceil((t(p) - g(p)) / c(p)))`。
次の1回が確定成功となるため、段階ごとの最大消費は **`(失敗回数 + 1) × c(p)`**。
これを現在+値から目標直前まで合計する。現在段階のゲージはその段だけに反映し、以後の段階は0とする。

```
最大必要石数 = Σ{ [ max(0, ceil((天井ライン - 現在ゲージ) / 1回コスト)) + 1 ] × 1回コスト }
```

この値はすべて天井まで失敗し続けた場合の**最大想定**であり、実際の石消費とは独立。
天井機能がOFFの場合は有限の保証上限がないため「必要総数の上限は計算できない」と表示する。

## 既存仕様との整合

- N/R/SR/UR/LRの強化成功率と消費コスト：既存 `js/data.js` / `js/core/enhance.js` の正本を再利用。
- 失敗時は強化値が下がらず、通常石が消費され、天井ゲージが加算。
- 強化値が上がると天井ゲージは0から再計算。
- 確定強化石 `guaranteedStones.free` / `paid` を一括操作では使用しない。
- 探索中のパーティ装備・未所持装備の一括強化は不可。
- 既存のセーブスキーマは変更しない。

## テスト項目

- [ ] 途中失敗後に成功して次段へ移行
- [ ] LR武器のように段階により1回コストと天井が変わる場合も、最新の段階で再計算
- [ ] 初期天井ゲージが貯まっている場合、その分だけ最大必要石が減る
- [ ] 所持石不足で次の抽選をせず停止、強化石の残数が負にならない
- [ ] 目標値の境界（現在+1、+99）、−/＋で確認状態をリセット
- [ ] 確定強化石が減らない。セーブは1実行につき1回
- [ ] 未所持・探索ロック中は実行不可
- [ ] iPhone Safariの表示・タップ領域・スクロールと保存結果を実機確認

## 正式版への移行条件

プロトタイプでは端末セーブが正本だが、正式Web/iOS版では所有権・素材残高・確率判定・天井の更新を**サーバー側で一括確定**させる。
リクエストの冪等性、二重消費防止、長時間実行の回数上限を追加する。課金用の確定強化石をこの処理に含めない。
