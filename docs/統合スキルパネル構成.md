# 統合スキルパネル構成

## 目的
職業固有スキルと汎用Ⅰ〜Ⅲの4本を、同一の盤面で把握・選択できるようにする。
FF12風の育成盤とDQ11風の密集したパネルの読みやすさを意識し、**習得条件やセーブ形式は変更しない**。

## 試作対象
- プロトタイプ版の剣士（warrior）のみ。既存の紋章盤／六角パネルを比較用に残す。
- 剣士は統合モードを初期表示とする。表示切替から旧「紋章盤」「六角パネル」に戻して比較可能。表示モードはセーブに追加しない。
- 戦士固有17個、汎用スロット3本×6個＝35個。各汎用枠の装着ツリーはキャラの状態から取得し、2候補間の交換機能を維持。
- 中央は固有、左は汎用Ⅰ、右は汎用Ⅱ、下は汎用Ⅲ。1枚のsceneへ配置。
- フィルター：全体／固有／汎Ⅰ／汎Ⅱ／汎Ⅲ／習得可。非選択枠を減光させるだけで習得状態は変更しない。

## アイコン仕様
ノードの表示に大きな漢字略称を使わず、形で種類を判別する。
- アクティブ技（物理）：**剣**
- 魔法・回復魔法・魔法的支援／MAG・MP強化：**杖**
- ATK・会心・腕力：**腕**
- DEF・被ダメージ軽減：**盾**
- SPD・俊敏：**足**
- HP・生命力・吸収・回復量：**体**
複数効果の場合は優先度に沿って代表アイコンを選ぶ。正確な効果は下部詳細で確認する。アイコンはオリジナルの軽量SVGで構築し、外部画像には依存しない。既存の六角パネルにもこのアイコン規則を適用する。

## 覚醒の将来拡張
- 覚醒Ⅰ・Ⅱ・Ⅲの予約領域を独立して設ける。初期は全て「準備中」で、クリック・習得・SP消費・保存を行わない。
- 覚醒はプレイ実績・職業固有の試練で解放する構想で、課金による基本職Lv99短縮とは切り離す。
- 初回は覚醒Ⅰから実装する想定。覚醒Ⅱ・Ⅲは将来のための表示領域のみ。
- 覚醒の保存フィールド、必要試練や効果は本試作で決めない。実際に仕様確定後に別PRで設計・移行を行う。

## データ整合性と操作
- ノード選択は [scopeKey,nodeId] によって元ツリーへ解決。固有・汎用は表示上のみ合成し、各ツリー定義とranksを渡して既存の詳細・習得処理を使う。
- SPは従来どおり4本の合計を表示。
- 汎用3枠の交換は既存の2段階確認、確定時のSPリセットに委譲する。
- スキルのマスター定義・二択・SPコスト・必要Lv・効果・データ保存形式は変更しない。
- ピンチ・ドラッグ・拡大縮小・全体表示も既存の共通関数を再利用。

## 検証
- GitHub Actionsでnpm testとWebリリースビルドを行う。
- Web版のiPhone実画面で「選択→詳細→習得」「汎用交換」「全体→フィルター」「覚醒予約」「小画面のナビ・ボタン重なり」を確認する。
- 実画面確認前は他職への自動適用を禁止し、旧UIは削除しない。

## 制限・今後の改良
- 35ノードの全体表示では個別マスが小さい。必要に応じズームを使う。タップ領域を確保するため、後日フィルター選択時の自動ズームを検討する。
- 汎用スキルは既存マスター定義のままであり、一般ツリーの選択肢や取得順は変更しない。
