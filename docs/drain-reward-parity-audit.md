# 実スキルHP吸収と通常・オフライン報酬の整合監査

更新日：2026-10-14。**通常/オフラインのEXP付与対象と自動分解設定の整合修正は本体適用済み。技固有の吸収率・OP上限・課金は未変更。**

## 検証方法とデータ出典

- `node --test tests/drain-reward-parity-audit.test.js`。監査ロジックは `tools/lib/drain-reward-parity-audit.js`。
- `tools/lib/load-data.js` から実際の `js/data.js` / `js/options.js` を読み、暗黒騎士の技 `drain`・既存種族/ツリー/セット装備・Extraの吸収OP値をそのまま使用。以前の合法ビルド監査（Lv99・98SP・スキル前提/排他・6点シリーズ装備）を再利用。
- 技は `js/core/battle.js` の `performCharacterAction` を実際に実行し、与ダメージ、イベントの吸収量、実際に増えたHPを検証。敵は固定HPを持つ監査ダミーとし、乱数は固定。技自体は**実データ**。
- 報酬は `js/model/run.js` の `winBattle`（通常）と `applyOfflineRun`（オフライン）を本物の `roster` / `inventory` と共に呼び、実在するスライムの経験値と実在するN装備の自動分解を同条件で比較。ドロップ数や回数まで再現した連続周回の確率試算ではない。

## 1. HP吸収の計算結果と設計上の問題

- 現行 `battle.js` は通常パッシブ吸収と技固有吸収を**加算**し、ダメージ × 合算吸収率を各ヒットごとに四捨五入してHPを回復する。回復後のHPは最大HPを超えない。
- 暗黒騎士の「吸命」固有吸収は60%。合法なLv99構成では、吸収OP0個でパッシブ合計39%、合算99%。Extra最高値の吸収OPを2個追加すると111%、6個では135%。これは吸収補正の合算値で、回復HPが最大HPを超えるわけではない。
- 既存ハード上限（技込み80%）、ソフト案A（天井92%）、ソフト案B（天井99%）のいずれも、**OP0時点の既存技・育成効果を弱める**。案BもOP0の合算99%が約91.5%に減る。OP2→OP6の増分も案Bで約1.8ポイントしかなく、さらに厳選する価値が低い。
- 吸収はヒット数・対象数ごとに計算されるため、割合だけでなく1行動あたりの実HP回復を検証してから、技固有部分とパッシブの上限設計を決めるべき。**現段階では既存の吸命を弱体化しない。**
- イベント `drained` は「与ダメージから計算した吸収HP」であり、キャラが最大HP近くの場合に実際に増えたHPと一致しないことがある。表示や周回ログにこの値を使う場合は注記が必要。

## 2. EXP・強化石の倍率と修正前の差（履歴）

- `js/model/roster.js` の `partyBonus(team,key)` は、そのチームの各メンバーの**装備セット・OPからの同種効果を加算**する。`js/model/run.js` は `1 + partyBonus` を通常勝利・オフライン精算の両方でEXP/自動分解素材に適用する。パーティ全体の別の上限は現在ない。
- 実在する Extra 最大値 +20% のEXP・強化石OPを5人がそれぞれ装備すると、どちらもパーティ補正が **+100%（2倍）** になる。補正計算は同じだが、ゲーム本体では丸めが戦闘/ドロップごとに入り、全周合計へ一律に掛けるのとは同値とは限らない。
- **通常：生存者のみEXP**、**オフライン：戦闘不能者を含む全員へEXP**。同一戦闘EXPでも結果が変わり得る。敗北を含む既存の進行ルールと矛盾しないか要方針決定。
- **通常：出撃時の自動分解レア度設定を保持**、**オフライン：精算時の `deps.autoDisassemble()` 設定を参照**。出撃後に設定を変えると同一ドロップでも保持/分解が異なる場合がある。セーブの再開・クラウド同期まで含め、どの時点の設定を正とするか決める必要がある。
- 自動分解の強化石に倍率が掛かるのは `receiveDrops` で確定した素材獲得量のみ。手動分解や報酬ドロップ数に追加倍率が掛かるわけではない。失敗周は原則ドロップなし（既存実装）。

## 3. オフライン報酬の整合修正（2026-10-14）

前回の監査で見つかった以下の2点について、**ゲーム本体の挙動を修正**した。OP上限やHP吸収の効果値は引き続き未変更。

- **EXP付与対象**：`offline.simulateRun` が勝利した戦闘ごとの生存キャラクターIDを保存し、`run.applyOfflineRun` はそのIDに含まれるメンバーだけへ経験値を付与。戦闘不能者は取得しない。戦闘1と戦闘2で生存者が異なる場合も各戦闘の情報を利用。敗北戦にはEXPなし。古いテスト・外部監査で生存者リストを渡さない形式の結果については互換処理を残す。
- **自動分解の出撃時設定**：`run.startRun` にあるスナップショット（ON/OFFと対象レア度）を `save.serialize` 経由で自動周回セーブへ保存する。`game.js` の画面復帰時にも同じ情報を渡す。`runOfflineProgressForTeam` はその設定を1回だけ確定し、オフライン中に何周進んでも共通に使用する。旧セーブで設定がない場合は現行設定にフォールバックする。
- **境界**：本体のドロップ数・EXP倍率・素材倍率・課金・キャラクターの既得EXPを一括書換しない。セーブの既存本体形式は維持し、`autoRepeat[].disassembleFilter` を任意追加する。インポート復元時の自動周回停止も維持。
- **検証**：`tests/offline.test.js`、`tests/run.test.js`、`tests/save.test.js`、`tests/drain-reward-parity-audit.test.js` に回帰を追加/更新。実際の戦闘と報酬の処理を呼び、旧形式や設定変更の再現も確認する。

## 4. HP吸収上限とパーティ報酬倍率（検討継続）

本体のEXP付与条件と分解設定を一致させても、技固有HP吸収の上限と、5人分を加算できるEXP・強化石倍率には別途調整が必要。**吸命60%を一律上限で弱体化する案は採用していない。**

## 以前の修正方針（履歴）

1. **吸命**：既存技固有吸収60%の価値を下げない専用計算案を作る。高吸収の耐久ビルドについて実HP増加量/ターン・敵のダメージ・多段・全体を考慮し、通常OPとの棲み分けを設計する。
2. **周回EXP**：通常とオフラインの戦闘不能者への経験値付与を統一するか、別ルールとしてプレイヤーに説明するか決める。勝利戦ごとの獲得であることも保持する。
3. **自動分解設定**：出撃時スナップショットをオフラインでも保持する案を第一候補とし、セーブ互換と復帰処理を確認する。
4. **素材・EXP倍率**：5人分で最大+100%となる現行OP例があるため、ソフトキャップ案（個人→パーティ全体）のどこに適用するかを先に決める。素材経済を変える修正は単独で導入しない。
5. 古いAPI名・未定義参照については、既存のコントラクトテストを維持し、今回の監査は実モデル関数を直接呼んで検証する。

## 受入範囲（更新後）

**今回の整合修正は `js/core/offline.js`、`js/model/run.js`、`js/model/save.js`、`js/ui/models.js`、`js/game.js` に適用済み。** 既存セーブの基本データと課金・技のパラメーター・OP上限は変更しない。新しい自動周回セーブには出撃時分解フィルタを付加し、旧セーブは現在のフィルタへフォールバックする。
