# Webプレリリース: 問い合わせフォームと20〜30人のテスター運用

- 状態: **問い合わせ導線の実装準備済み / Googleフォーム本体の作成とURL設定は未完了 / テスター制限は未実装**
- 対象: `ios-hackslash-prototype` の Preview。正式Web版 `swordcrest` への移植時にはGoogle認証後のサーバー側ゲートを利用する。
- 既存のクラウドセーブ・ショップ・ゲーム本体には変更を加えない。

## 1. フォーム作成（運営者が1回実行）

1. [Google Apps Script](https://script.google.com/) で新規プロジェクトを作成。
2. `tools/create-feedback-form.gs` を貼り、`createSwordcrestFeedbackForm` を一度だけ実行してGoogle側の権限を承認。
3. 実行ログから「回答URL」を取得。**編集URL・回答スプレッドシートURLはプレイヤーへ配布しない**。
4. `js/contact-config.js` の `window.SC_CONTACT_FORM_URL` に回答URLを設定してデプロイ。
5. Googleフォームの回答者アクセス設定を確認し、テスト端末のシークレットウィンドウ/iPhone Safari/Chromeで回答送信を試験。
6. オーナーのみ回答できるスプレッドシートにアクセス可能なことを確認し、フォーム側の「新しい回答についてのメール通知」を設定。

補足: 設定されたURLがGoogleフォームの公開回答URL（`forms.gle` または `docs.google.com/forms/d/.../viewform`）以外なら導線は表示されない。未設定でダミーURLに遷移することはない。ポップアップ処理は用いず、実ユーザーが押したアンカーから新規タブを開く。

## 2. フォームの質問

- 必須: お問い合わせ種別、発生した画面、内容
- 任意: 再現手順、利用環境、ゲームバージョン、返信先メールアドレス
- 回答回数の制限は無効（不具合を繰り返し報告可能）
- メール収集は自動では行わず、手入力も任意。ファイルアップロードは使用しない
- 回答の一覧を回答者に公開しない。パスワードやプレイデータ、決済情報を送らせない
- テスト終了時は「回答を受付中」をオフ、必要な対応完了後に情報保持・削除を見直す

## 3. 20〜30人のアクセス制限（未実装・必須）

**URLを非公開にするだけではアクセス制限にならない。Firebaseの無料枠もユーザー数ではなく実利用量で決まる。**

現行PreviewはFirebase匿名認証（`js/cloud.js`）を用いるため、招待対象者のメールとの紐付けができない。クライアント側JavaScriptのメール配列や単純な合言葉は認可として使わない。

正式な限定テストを開始する前に以下を別PRで実装する:

1. Preview/Staging専用のFirebaseプロジェクトとWeb配信オリジンを分離。本番用の購入/保存台帳や正式ユーザーを混在させない
2. Firebase Googleログインに統一し、サーバー管理の招待許可リストを用意。本人確認済みの `uid` をトランザクションで最大30件だけアクティブ登録できるようにする
3. ゲームの正式保存・課金テスト・アカウントAPIは、**トークン検証+uidの許可状態**を各リクエストで検証。クライアントによるUID申告だけを信用しない
4. FirestoreのSDK直アクセスが残る場合は本人かつ許可UIDに限定するRulesを用い、Emulatorで許可・拒否・失効を検証する。Admin SDK経由APIではRulesが効かないのでAPI側でも拒否する
5. 一般的な静的ホスティングではURLを知る人がJavaScriptを取得できる点に注意。ブラウザに配布したゲームコードやローカルセーブを完全に禁止することはできない。守る対象は公式アカウント、クラウド保存、課金・付与とサーバー利用権限
6. テスト終了時にはアクティブ招待を失効し、公式APIアクセスを拒否。URL変更やFirebaseドメイン設定だけでは失効を代替しない

## 4. 受入・負荷計測

- [ ] 回答URLは実在し、iPhone Safari/iPhone Chrome/PC Chromeで別タブから回答送信可能
- [ ] フォームへ2回以上送信でき、スプレッドシートへ記録される
- [ ] 未設定・悪意あるURLはUI非表示で、セーブやクラウド通信に副作用がない
- [ ] 許可されたUIDのみバックアップ/ゲームAPIにアクセス可能、未招待/31人目/失効ユーザーは拒否される（将来の別PR）
- [ ] 連続自動周回でFirestore読み書き・Host帯域・Cloud Functions呼び出し・エラー率を測定
- [ ] テスト決済はStripe Test Mode等のサンドボックスのみ、本番請求は禁止
- [ ] 1週間程度のテスター検証後に不具合を重大度・発生頻度・再現性で整理して修正優先度を決定

### セルフレビュー観点

- 外部リンクは固定のGoogleドメインだけを許可し、`https:`以外と編集URLを拒否
- `target="_blank"` / `rel="noopener noreferrer"`、DOM生成時にフォームの任意HTMLを実行しない
- `SC_CONTACT_FORM_URL` は公開回答URLだけ。Google編集権限・スプレッドシート・秘密情報はリポジトリへ書かない
- フォーム設定は無料枠の節約にはなるが、認証・利用人数制限の代わりにはならない
