# スキルツリー蜘蛛の巣UI設計（剣士先行）

## 対象・目的
- プロトタイプ版 `ios-hackslash-prototype`。2026-10-25時点は基本職「せんし」の固有ツリー「剛勇の心得」のUI先行検証。
- `EXCLUSIVE_TREES.warrior` の現存17ノードを、中心＋6方向（基礎/猛攻/破砕/覇道/鉄壁/装備）×3リングへ配置。
- 覚醒・スキルブックによるツリー全体入れ替え・実際のスキル構造の改訂は今回行わない。

## 変更範囲
- `js/ui/detail-tree.js` に剣士用 `WARRIOR_WEB_LAYOUT` と描画関数を置き、**現職が`warrior`（せんし）かつ固有ツリーIDが`warrior`の時だけ適用する**。同じ固有ツリーを共有する`けんごう`は従来UIを維持。
- 固有ツリー以外と汎用ツリー3枠は従来の縦分岐図を継続。新しいノードIDが追加された場合は、欠けたノードを隠さず従来の縦分岐図へフォールバック。
- ノードID、`prerequisites`、`exclusiveGroup`、`reqLevel`、`costByRank`、`effects`、`ability` の正本は`js/data.js`。このデータは編集しない。
- `getTreeState`、`canAcquireNode`、`acquireNode`、`resetTree`、SP計算、保存形式を変えない。既存の詳細シートに名前・効果・習得ボタンを表示する。

- 放射線・六角環は**背景ガイド**。習得に必要な実線は元の`prerequisites`に沿うため、方向を横断することもある。
- 習得済み＝青白い魔力光、習得可能＝古金、その他＝暗い鉄色。現行通りノードを押せば習得・前提条件等の詳細が画面下に出る。
- ノードの中身は省スペースな一文字略称。完全な名前はボタンのアクセス可能なラベル・選択時の詳細欄で案内。
- 操作: iPhoneの一本指ドラッグと二本指ピンチ拡大（1〜2.5倍）、PCの余白ドラッグ、ズーム±と「全体」でリセット。
- スキル取得による画面再描画時も拡大位置を一時記憶。位置情報はセーブデータに含めない。

## 継続検討と実機確認
- 小さなiPhone（狭い縦幅）でノード間隔・下部詳細シートの重なり・スクロール動作を確認。
- ノードタップ、ピンチ/ドラッグ、全体表示、前提ロック、二択排他、探索中の取得不可を確認。
- 他ジョブへ展開する前に読みやすさ・リング配置・ノード略称を調整する。
- スキルブック（ツリー丸ごと交換）と覚醒Ⅰ〜Ⅲは別途設計書を起こすまで実装しない。

## 回帰テスト
`tests/warrior-web-tree-ui.test.js` で17ノード表示、実際の前提線、リング・方向、ノード選択、ズーム、既存縦分岐図と元の正本を検証。

## 2026-10-25 ギルド世界観への意匠刷新（せんしのみ）
- 実際のプロトタイプの探索/タイトル背景 `#app`・`icons/explore-guild.jpg`・他画面は**変更しない**。画像生成の見本は装飾の参考のみで、スクリーンショット画像を操作画面に重ねることはしない。
- スキルツリーの領域だけに、半透明の黒青緑・古金の二重枠・同心円・細かい刻印・中央の剣紋章を重ね、世界観を既存のギルドUIに合わせる。
- 習得済みノードおよび実前提線は青白い魔力、習得可能は淡い金色、未取得は黒鉄。取得済みと排他の二択は封印石のように表示。
- ノードは既存17個のまま。表示アイコンは軽量SVGで、火力/耐久/装備/奥義の見た目を変える。操作系（タップ、ピンチ、ドラッグ、全体表示）も継続。
- ノード詳細下部の名称・必要SP・必要Lv・前提を古金のカードで表示。**習得可否・必要SP・前提・レベル・効果・保存形式はすべて既存ロジック**を使用。
- CSSは `.warrior-crest-section`、`.tree-web--crest`、`.warrior-crest-detail` に限定し、ほかの職業と汎用ツリー3枠の見た目を変えない。
- 演出は選択可能ノードと中央枠の弱い脈動に限定。端末の「視差効果を減らす」に相当する `prefers-reduced-motion` を尊重。
- CSS/JSのキャッシュ番号を更新してiPhone Safariで反映されやすくする。本番リポジトリ・デプロイは対象外。

4. 古いセーブからでもスキル習得状態が維持されるか。
