# クローズドβ：X応募者の公平な抽選手順

## 目的と前提
X（旧Twitter）で募集した応募者のうち、応募条件を満たした人から抽選で初期10人程度を選び、辞退枠は補欠順位で繰り上げる。最大30人の招待は**サーバー側認証の上限**で担保し、抽選ツールでの件数制限だけを信用しない。

**このツールは抽選専用**。Xから応募者を取得したり、DMを送ったり、Firebaseのアクセスを許可したりはしない。応募・当選ユーザー名をGitHubや公開コメントに貼らない。

## 手順

1. 公式Xアカウントで応募締切を告知。複数アカウント応募は不可、1人1枠、応募資格、抽選人数、結果連絡、辞退時繰上げなどを予告
2. 応募締切後、リプライ/応募フォームなど**指定した単一の応募方法**から全件を取得する。X検索だけではすべてが表示されるとは限らないので通知や専用フォームと突き合わせる
3. 1行1ユーザー名のテキストファイルを**ローカル端末にのみ**作成する（例: `/private/tmp/swordcrest-applicants.txt`）。`@alice` / `bob` のどちらでも可
4. 明らかな複数アカウント/重複応募、締切後の応募、無効な応募を手作業で除外。抽選ツールは**大文字・小文字と@の重複しか自動検出しない**ため、同一人物の複数アカウントまでは検知できない
5. 抽選：
   ```bash
   node tools/beta-lottery.js /private/tmp/swordcrest-applicants.txt 10
   ```
6. 端末内に抽選ログ（日時、応募件数、SHA-256、当選者、補欠順位）を保存。ハッシュは応募リストの正規化・ソートから作るので、誰でも同じリストなら同じハッシュが得られる（当選結果は暗号学的乱数なので再現しない）
7. 公式Xアカウントから当選者にのみ個別連絡し、認証・参加同意が完了したらサーバー側で招待を有効化。辞退/連絡期限切れならログの補欠順位どおりに繰り上げる
8. 最初の10人で保存、問い合わせ、Firebase負荷、安全性を確認できた場合のみ累計20〜30人へ拡大する。再抽選する場合も抽選方法を事前告知
9. 募集・運用目的が終了し保持が不要になった応募ファイル・抽選ログ・連絡履歴は、告知した保持期間/削除方針に従い削除する

## 安全・公平性上の注意
- Node.js標準の `crypto.randomInt` とFisher-Yatesで抽選し、`Math.random` やリポスト回数による重み付けはしない
- 手作業の応募リストに漏れがあると公平な抽選にならない。締切時の入力リスト確定手順を記録する
- X上で同じ投稿の大量リポスト・複数応募を促さない。Xキャンペーン実施ガイドラインに従う
- ゲーム側の「無料ショップ」や正式版の購入権利と混同しない。応募は無料、β進行は正式版に移行しない
- 当選者に送るリンクのドメインを公式アカウントで案内し、認証コード・パスワードをDMで求めない
- 応募ファイルは**Git管理領域に置かない**（非公開リポジトリでも個人情報の保存先にしない）
