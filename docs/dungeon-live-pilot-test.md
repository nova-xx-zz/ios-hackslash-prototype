# ダンジョン3F・5F：本体接続パイロット実装／実機テスト

> 2026-10-16 / 対象: prototype PR #104 / **本番配信は禁止**。（2026-10-19更新：mainに統合済み。ただし検証版（preview）で `?dungeonPilot=1` を付けた時だけ動き、保存先も `qpdungeonpilot:` に分離。通常のURL・正式配信ビルドでは無効）
> 制限: 3F `plains` `forest`、5F `cave` のみ。
> [全体仕様](dungeon-boss-design.md) / [35ダンジョン割当](dungeon-floor-assignments.md) / [隔離プレビュー](../dungeon-preview.html)

## どこまで実装したか

- `?dungeonPilot=1` を指定した**試験URLのみ**、既存run.jsの`startRun`で全階層の戦闘回数・ボス配置を一括抽選し、通常戦闘ごとに敵1～5体をランダム選出する。
- 本物の`makeEnemy`、`battle.js`自動戦闘、`run.winBattle`経験値/ドロップ、`finishRun`を利用。ボスを含め最大5体。
- ロックゴーレムがHP60%以下になったときに1回だけ防御倍率+25%。戦闘ログに理由を表示。3Fボスは単純1フェーズ。
- 宝箱/鍵付き宝箱/泉の周辺魔力は**非ブロッキング**。泉は水を自動で飲まない。泉のDEFバフ/デバフは通常戦闘とオフライン戦闘に反映する。
- 解錠術の探索専用スキルを追加済み。盗賊Lv5／忍者Lv1から習得し、鍵付き宝箱を自動で1回判定（基準成功率45%）。詳しくは[解錠術パイロット](thief-lockpick-pilot.md)。
- 通常・自動周回・オフライン精算でもボス、敵数、宝箱/泉、ドロップ・全滅ロストの共通ルールを適用する。
- 完全踏破でのみ`pendingDrops`を確定。UR/LRや中ボス・宝箱も途中で持ち帰らず、全滅/timeout/撤退で**全ロスト**。所持済み装備は消えない。
- パイロット実戦闘では未討伐を誤って`winBattle`しない・二重勝利/二重`finishRun`を避けるガードを追加。

## 既存セーブの分離（重要）

- `js/core/storage.js`でpilot URL専用の `qpdungeonpilot:` を利用し、通常版`jobquest_save_v1`と保存領域を分離する。**既存セーブは読み込まず、pilotは新規セーブで開始**。
- pilotでは`js/cloud.js`のFirebase同期を無効化する。正式版ではruntime channelが`production`となるためURLオプトインではpilot起動不可。
- 通常URL（`?dungeonPilot=1`なし）は旧仕様、別セーブのまま変化しない。debugモードとの混在は避ける。

## 重要な未完了（本番導入ブロッカー）

1. **戦闘中のrunの再起動復元**：元のsave形式は戦闘中の敵HP/MP・全階層floorPlans・乱数状態を完全復元しない。今回も保存形式は未改修。`?dungeonPilot=1`の戦闘中にページ再読込すると同一runの計画に戻る保証はない。再ロードして再抽選しないという本仕様は、この点を修正するまで**未達**。
2. **ボスの正式バランス**：既存ダンジョン推奨レベルと現行の装備/OPを使った3F/5Fの実勝率・所要時間の統計検証が未完了。難易度数値・レア出現率も暫定。
3. **盗賊解錠スキル**：Lv5/忍者Lv1の探索専用スキルとして試験実装。通常ジョブスキルとは別扱いで、今後体感に合わせて成功率45%を調整する。
4. **報酬永続化/不正**：ランタイム二重呼び出しは抑止したが、クライアント保存改ざんに対する完全耐性・原子的なrun終了と保存のCASはサーバー側での設計が必要。
5. **オフライン結果の完全一致**：実戦闘エンジンは共有する一方、端末の一時中断時のrun破棄・オフライン再周回の乱数引き直しなど元の運用差が残るため、長期自動周回と端末休止を重点検証する。
6. 35ダンジョンの10F/15Fはまだ本体で有効化しない。中ボスの専用挙動も未統合。
