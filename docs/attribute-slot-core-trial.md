## 設計値とテストした操作

### 属性

- 10種: 土→炎→氷→雷→木→土（有利 ×1.30・逆方向 ×0.80）、龍↔血塗られた / 混沌↔金は両方向 ×1.25、虚無→他9属性 ×1.15、虚無→虚無 ×1.00。
- 一般の対土反転OPは炎→土の不利 ×0.80 を有利 ×1.30 にするが、完全無効の敵に対しては **0倍を維持**。
- dungeon.voidMultiplier = 0.7（抑制）/ 1.4（活性）は **試験用の仮値**。虚無攻撃のときだけ適用される。
- dungeon.blockedElements、enemy.immuneElements、enemy.elementMultipliers[element] = 0 は完全無効。倍率0を「未設定（1）」に変換しない。
- 通常属性で虚無防御の相性は、現段階で合意のない不利を新設せず中立とした。技属性・武器属性の解決は未統合。
- 期待値計算：土敵に木×1.30、炎×0.80、炎＋対土反転×1.30、虚無×1.15（抑制時×0.805、免疫時×0）。

### OP上限と旧セーブ

- inspect(item) は上限・天然/継承数・穴解放数・次の強化閾値・追加可否を返し、**入力を変更しない**。
- openNextSocket(item) は+条件（例SR+50→1穴、+99→2穴）と総OP上限を確認して、穴を開けた **新しいアイテムオブジェクト**を返す。
- extractNatural(item,index) は1個の天然OPのみ取り出し、**元の武器ID・+値・他のOPを維持**する。継承済みOPの再抽出は不可。
- validateInheritance(item,candidate) は **武器元のレアリティ < 継承先武器レアリティ**、総OP上限、穴の空き、同一OP禁止、特殊OP上限を検証。appendInherited は成功時相当の**純粋な状態更新だけ**をシミュレーションする。
- 新たな継承素材の属性 key、実数値 value、OPランク rank、元武器ランク sourceItemRarity を別保存する。
- 旧セーブの {key,value}（originを持たない）を天然OPとして読み、**値・個数を勝手に切り捨てない**。新仕様の総枠上限を超える場合は overCapacity を返し、新規継承を禁止。抽出して上限内に戻す。
- 現時点では天然OPを新規ドロップで最大1つに抑える**候補**を、ランダムドロップ生成には実装していない。現行のハード/エクストラのOP数はそのまま。
- 特殊OPは候補の special:true または group:"special" として明示し、1武器につき1件に制限。現行全OPデータへの分類のマッピングは、本体統合時に作成する。

## 今回触れていない部分（重要）

- js/core/battle.js の旧 res.el[element] の **0が判定されない処理**は未修正。新属性判定を本体へ接続するときに、戦闘・AI・オフライン周回をまとめて移行する。
- 独立モジュールは抽出液の消費・UR/LRの成否判定・天井のOP別管理・課金用確定液を扱わない。既存の試作工房（js/core/option-inheritance-trial.js）も今回変更していない。
- 装備の天然OPが1〜3個付く旧ドロップ、低レア希少OPを守る自動分解、セーブ移行、旧技/敵属性の個別置換も今回は未変更。
- 本番でサーバーが管理すべきアイテム移動・課金権利・消費・抽選・天井は、このクライアントの単体関数だけで認可しない。
