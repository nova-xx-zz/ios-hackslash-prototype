# 実ゲームデータによるソフトキャップ比較・セルフRV

更新日：2026-10-14

> **比較は未採用の候補案であり、ゲーム本体・課金・セーブには適用しない。** 実際の職業・種族・スキル・装備セット・EXTRAモードのOP効果を読み込んで計算したもの。ユーザーのプレイデータそのものではない。

## 再現方法

- node tools/compare-soft-caps.js
- node --test tests/soft-cap-real-data.test.js
- 実データは js/data.js と js/options.js。読み取りは tools/lib/load-data.js、Lv99/98SP・スキル分岐・6点セットの検証は tools/lib/real-option-cap-audit.js、比較式は tools/lib/soft-cap-real-data.js。
- 7ビルドについて、同一シリーズ6点を装備し、対象OPを0個・2個・6個付けた場合を比較。OPは各部位にEXTRA最高値1件ずつの厳選ストレスケース。ドロップ率や獲得コストは含めない。
- 全職業/全分岐/全パーティを網羅した理論最大値ではない。全身6個同種OPは極端な厳選を想定している。

## 計算案

- 旧ハード：既存の試作用上限を超えると増分はゼロ。
- ソフトA（慎重）とソフトB（収集重視）：xが閾値t以下ならx、超えた場合 t + (u-t) × (1-exp(-(x-t)/(u-t))) 。uは天井。OPの増分が段階的に小さくなるがゼロにはならない。
- HP吸収はパッシブ→技固有の吸収を加算→全体の上限を順に計算。被ダメージ増加・MPコスト増加などの負効果を取り除かない。

| 指標 | 軟上限開始 | ソフトAの天井 | ソフトBの天井 |
|---|---:|---:|---:|
| 会心率（基礎10%込み） | 75% | 90% | 97% |

| 技込みHP吸収 | 80% | 92% | 99% |

### 上限で既存スキルが弱くなる問題

暗黒騎士はOP0でも現在の実データで技込みHP吸収99%。ハード案は80%、ソフトAは約89.0%、ソフトBでも約91.5%まで落ちる。**ソフトキャップは既存スキルの弱体化を自動的に解消しない**。技固有の吸収と通常パッシブの処理を分け、HPの回復上限、連続攻撃、複数敵攻撃の回復量を合わせて別途設計する。

忍者のOP0会心68%、大神官のOP0回復+94%、魔法使いのOP0MP軽減50.7%は閾値未満で元の数値を維持する。

## セルフRVと次の判断

- 実データの出典とスキル合法性を前回の監査テストに連結している。旧ハード結果は旧試作APIと一致する。
- ソフト上限の境界・単調増加・有限天井・マイナスデバフ維持・全7ビルドの0/2/6OP比較・固定入力の再現性を自動テストする。
- 会心率94%に近づく案Bは強すぎる可能性がある。高難度の戦闘や敵AIへの影響を試すまで採用を保留。
- 被ダメ軽減の天井を82%まで許す案Bは敵ダメージを無意味にする可能性がある。実戦検証が必要。
- 周回報酬の+94%近辺を許す場合、パーティ5人の効果がどう重なるか、オフライン獲得量、サーバー経済・課金設計まで確認する必要がある。
- **結論：会心・回復・報酬・MP軽減はソフトキャップを検討する価値あり。HP吸収は別ルールが必要。数値は未確定。**
- 次工程はHP吸収の技固有ルールと、通常/オフライン周回の報酬倍率の実装検証。戦闘・報酬・本番への直接変更はまだ行わない。
