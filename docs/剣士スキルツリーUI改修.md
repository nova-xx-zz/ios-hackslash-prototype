# 剣士スキルツリーUI改修（剛勇の紋章盤・専用画面化）

2026-10-25 / プロトタイプ版 `ios-hackslash-prototype` のみ。
前段の設計は `スキルツリー蜘蛛の巣UI設計.md`（6方向×3リングの導入）。本書はその見た目を「スキルツリー専用画面」へ作り直した改修の設計で、表示に関しては本書が優先する。

## 対象範囲
- 基本職 **せんし（`job === "warrior"`）の固有ツリー「剛勇の心得」** を表示するキャラ詳細の「ツリー」タブ。
- 変更ファイル: `js/ui/detail-tree.js`（表示）、`css/style.css`（せんし限定の意匠）、`index.html`（キャッシュ番号）、`tests/warrior-web-tree-ui.test.js`、本書。
- ノードは正本 `EXCLUSIVE_TREES.warrior` の17個をそのまま使う。

## せんしのみに適用する理由
- 理想イメージ（剣の紋章を中心にした6方向の盤）は、せんしの「剛勇の心得」に合わせた意匠で、方向名（基礎/猛攻/破砕/覇道/鉄壁/装備）もせんしのノード構成に対応している。
- `けんごう` は同じ固有ツリーを参照するが、上位職として別の意匠を当てる余地を残すため従来UIのまま（判定 `isWarriorCrestWeb` は `c.job === "warrior"` を条件にする）。
- 他職・汎用ツリー3枠は従来の縦分岐図。ノードIDが追加されて配置表に無い場合も、隠さず従来の縦分岐図へ戻す。

## UI方針
「ギルド背景は維持しながら、せんしのツリータブだけは独立した全高のスキルツリー専用画面に見せる」。通常の仲間詳細ヘッダー・下部タブ・グローバルナビは、この表示中に限って非表示にする。

### 画面構成（上から）
1. **専用見出し**: `SWORD CREST ✦` ＋ 大きな「スキルツリー」、右に宝石アイコン付きの SP 札（残り／合計）と「リセット」札（費用表示。確認2回押し・費用・処理は共通のまま）。
2. **紋章盤**（タブ幅いっぱいの正方形）。円盤の外に空く四隅を使い、左上に剣紋章＋「せんし」「剛勇の心得」、右上に拡大縮小（−／＋／全体）を重ねる。カード枠は外し（`.job-char-card:has(> .tree-tab--crest)`）、盤面をギルド背景の上に直接置く。
3. 4つの横並びタブ（せんし／汎用Ⅰ／汎用Ⅱ／汎用Ⅲ）で1つだけ表示。汎用は選択時に従来の縦分岐図を表示する。
4. 盤面の下へ、選択中スキルの詳細パネルをスクロール可能な形で常時表示（固有は剣撃突きを初期選択）。

### 盤面
- 中央: 大きな剣の紋章（SVGの塗り＋線）。古金の多重リング、四方星、六芒の魔法陣、導線リング。「剣撃突き」習得で紋章が灯る（弱い脈動）。
- 外周: 古金の二重外枠、目盛72本、フォント非依存の線刻ルーン帯。
- 背景ガイド: 3本の同心円（点線）と6本の放射線（破線）、枝ごとの淡い色の扇。**当たり判定なし**。
- 方向札: 6方向に古金の飾り札（六角の札形・枝色の下線と文字の光）。斜め4方向は外周ノードと重ならないよう上下へずらして外枠に掛ける。
- 枝の色（控えめ）: 基礎=青 / 猛攻=赤 / 破砕=金橙 / 覇道=紫 / 鉄壁=青灰 / 装備=緑。全体は古金・青緑基調。

### ノード配置
基礎の3つは外周→中心へ進み、紋章に至ると「剣撃突き」から中心の導線を通って残りの方向へ広がる構成にした（実際の前提 `w3 → w4a/w4b/w5/w_acc2` と一致し、線が盤面を横切らない）。

| 方向 | 中心寄り | 中段 | 外周 |
|---|---|---|---|
| 基礎 | 剣撃突き w3 | 戦いの勘 w2 | 鍛えた腕 w1 |
| 猛攻 | 猛攻の構え w4b | 豪腕 w7b | 覇気 w10b |
| 破砕 | 鎧砕き w5 | 剛力 w6 | 剣の頂 w11 |
| 覇道 | 鬨の声 w8 | 歴戦の体 w9 | 剛勇覇斬 w12（奥義） |
| 鉄壁 | 不動の構え w4a | 鉄壁の構え w7a | 闘志 w10a |
| 装備 | 装備の極意 w_acc2 | 装備の心得 w_acc1 | （空き） |

- 座標は `WARRIOR_WEB_LAYOUT`（方向・リング・微調整）だけで決まり、ツリー構造には触れない。
- 二択の反対側（猛攻⇔鉄壁）は盤の反対側にあるため、`w6→w7a` は覇道の内側を回り込む導線、`w9→w10b` は破砕の外側を回る弧で描く。

### 接続線（実際の前提線）
- `prerequisites` 1件につき1本（計16本）。親→子へ、円に沿って曲がる線（中心を突っ切らない）。
- 暗い溝の上に線を引く2層構造。交差しても上下関係が読める。背景ガイド（細い点線・破線）とは太さ・実線で区別。
- 習得済みルート: 青白い線＋外光＋白い粒が流れる。習得可能な先への線: 金色＋ゆっくり流れる。未取得: 細い鉄色。封印された先: 赤錆の点線。

## ノードの状態表現
| 状態 | 見た目 |
|---|---|
| 習得済み | 青白い魔力光（縁は白銀、内側は深い青、外光） |
| 習得可能 | 金色に発光（外光が脈動） |
| 未解放（前提未達） | 暗い鉄色。刻印は残す |
| 未解放（Lv不足） | 封印石（暗い石色＋錠前の刻印、内線を点線） |
| 二択で取れない側 | 赤錆の封印（錠前＋鎖の刻印） |
| 選択中 | 古金の点線リングがゆっくり回る |

形で種別を示す: パッシブ=円 / アクティブ=菱形 / 装備=六角の宝石印章 / 奥義 w12=八芒星の大型ノード。内側の細線が枝の色。刻印は17ノードそれぞれ別の線画SVG（画像ファイル不使用）。

## 下部詳細パネル方針
- せんしの専用画面では `#detailSheet` の固定枠は使わず、盤面の直下に `crest-inline-detail` を配置する。小さなiPhoneでも詳細と習得ボタンをスクロールして表示できる。
- ほかの職業の固定詳細 `#detailSheet` は従来どおり維持する。
- 左: 大きなアイコン（ノードと同じ形・状態色＋古金の目盛環）。右: スキル名、種別・方向・状態の札、必要SP・必要Lv・前提（二択なら相手）。その下に説明文（正本 `desc`）、技の補足（`ability.desc` が説明に含まれない時のみ）、短いフレーバー文。
- 下部に大きな「習得する」ボタン（使用SPと残りSP）。押せない時は理由（探索中・二択・Lv・前提・SP不足）をボタン内に表示。**可否は `canAcquireNode`、習得は `acquireNode` をそのまま呼ぶ**。習得済みは青白い「習得済み」表示。
- 古金の装飾枠・暗い背景・高コントラストの文字。縦が短い端末（高さ720px以下）はアイコン縮小・フレーバー省略で盤面を広く残す。
- ノードを選んだ直後だけ、選択ノードが詳細パネルに隠れないよう画面内へ寄せる（スクロール位置は保存しない）。

## 操作
- タップでノード選択。ピンチ拡大（1〜2.5倍）、拡大中の1本指ドラッグ、−／＋／全体、PCは余白ドラッグ。
- 等倍時の1本指は画面の縦スクロールに任せる（盤面の下の詳細パネルまで移動できる）。拡大中だけ盤面がドラッグを専有（`touch-action` を切替）。
- 視点（拡大率・位置）は再描画で保持し、セーブには含めない。
- `prefers-reduced-motion` では流れ・脈動・回転を止める。

## 非対象範囲（変更しない）
- スキル効果・必要SP・必要Lv・前提条件・排他条件・SP計算・習得処理・振り直し処理・セーブデータ構造。
- けんごう・他職のツリーUI、汎用ツリー自体の描画・習得仕様、ギルド背景画像・他画面のヘッダー・下部タブ。せんし以外には表示制御を適用しない。
- 覚醒Ⅰ〜Ⅲ、スキルブック（ツリー入れ替え）、ツリー構造の変更。正式版 `swordcrest` への反映。

## 2026-10-25 レイアウト再修正：参考画像に近い全高専用画面

### 現状との差分
スクリーンショット比較で、既存の仲間詳細バーに縦方向のスペースを取られること、汎用ツリー3本が固有の下へ続いて画面全体が間延びすること、詳細が選択時に画面下の別シートで開いて盤面と分離することが判明。外周・ノード装飾だけでは再現しきれないため、せんしに限定して画面の器も見直した。

### 実装
- `js/ui/detail.js` の `renderCharDetail` で **detailTab=tree かつ job=warrior** の時だけ `#screen-chardetail` に `warrior-crest-view` クラスを付与し、既存の仲間詳細ヘッダー／下部5タブを隠す。
- 全高レイアウト専用の左上「戻る」は `detailTab=stats` に戻り、従来の仲間詳細を表示できる。画面上部で名前と前後の仲間への移動も可能。
- グローバルナビは専用画面表示中のみ CSS `:has()` で隠し、スクロール領域を安全領域の下まで拡張する。他画面のナビを変更しない。
- 参考画像の「SWORD CREST」表示と大きな「スキルツリー」見出し、SP／リセット、四分割タブを上部にまとめた。
- せんしでは固有・汎用Ⅰ・汎用Ⅱ・汎用Ⅲを**排他的に1つだけ表示**。汎用ツリーのノード描画と交換・習得ロジックは従来のまま。
- 職業紋章・職名は円盤の上に独立配置して重なりを回避。固有ツリーの17ノードと接続関係は維持。
- 剣撃突きを初期選択し、従来の既存専用スキル詳細・習得ボタンを盤面直下へ常設。スキルの選択・SP消費と保存は従来のAPIを呼ぶ。汎用では選択中の既存詳細を同じ領域に表示。
- 探索中はもとの `canAcquireNode`・`canResetTree` 等の操作不可判定を維持する一方、戻る・タブ選択・閲覧は許す。
- 拡大・縮小・ドラッグ、低モーション設定、画面幅の安全余白は維持。

## 2026-10-26 調整：線の視認性と追加縮小段階

### 課題
iPhone実機のせんし専用画面で、ルートの発光・ガイド線が重なって見え、紋章盤の読みやすさを下げていた。また「−」ボタンがスケール1倍を下限としていたため、全体表示から縮小できなかった。

### 修正
- **描画対象の17ノード・実前提線16本は維持。** ノード間の接続条件・セーブデータには触れない。
- 古金の補助円、放射線、淡い扇、ルーン、未解放と排他の経路は透明度や線幅を下げる。装飾線の主張は抑え、実前提線の存在は残す。
- 習得済みルートは青白、習得可能ルートは金色という区別を残しつつ、溝・発光グロー・光の流れを細く弱くする。
- スケールは **初期・全体表示0.92倍／最小0.80倍／最大2.50倍**。±ボタンは0.12刻みで、最小時の「−」と最大時の「＋」はそれ以上動かない。
- **1倍以下は縦スクロール優先**、1倍超はピンチ・ドラッグで盤面を操作。縮小時にパン領域がマイナスになって盤面がずれないよう、移動可能範囲を0に固定する。全体表示は移動量を0に戻す。
- 新しい表示サイズはセーブせず、再描画時のみ一時維持。他職・汎用ツリーのCSS/ロジックは変更しない。
- iPhoneでのキャッシュ更新のためCSSとツリーJSのクエリ番号を更新する。

### 確認観点
1. 初期0.92→「−」0.80→さらに「−」0.80、＋で0.92に戻る。全体表示で0.92・中央に戻る。
2. ピンチで最小0.80・最大2.50を超えず、0.80時にもスクロールできる。
3. 習得済み／可能／未解放の色と16本の実前提線は読めるが、以前より発光が控えめ。
4. けんごう、他職、汎用3枠、SP消費、習得判定は従来通り。

## 2026-10-26 「1画面に全表示」参考画像準拠の改修（レビュー待ち）

### 不具合・目的
実機でせんし専用ツリーが、上部ヘッダー・職業紹介・正方形盤面・詳細カードを積み重ねており、スキル説明や「習得する」ボタンが下へ隠れた。理想画像はツリーと詳細・習得操作が1枚の縦画面内に収まっているため、縦スクロールせずに操作できるレイアウトを基本とする。

### レイアウト
- **基本職せんしのみ**: `#detailBody` → `job-char-card` → `tree-tab--crest` → `warrior-crest-section` をFlex縦方向で必要高さに割り当てる。
- ヘッダー/戻る/仲間切替、SP/リセット、4タブは維持したまま縦方向の余白を圧縮。**リセット札はSP未使用時も常設し、操作不可**（課金・確認仕様は変更しない）。
- 職名/剣紋章の小見出しと±/全体の操作は円盤の左右上部に重ね、従来の約60pxの専用見出し行をなくす。
- 正方形盤面は従来の画面幅固定表示を廃し、ヘッダーとスキル詳細で使用する高さを引いた **残りの縦幅** に収める（CSS Flex とアスペクト比1:1）。小さくなってもタップ/ピンチ拡大が使える。
- 下部詳細は古金の装飾と大型アイコンの印象は維持し、アイコンサイズ・余白・説明文をコンパクト化。`習得する` 操作は42px以上を確保。ゲーム上必要なスキル効果、必要SP、必要Lv、前提条件は省略しない。
- 実装済みの補足用フレーバー文/重複の技説明はこの画面では省略する（データ自体は残す）。`習得済み` 表示も小さくする。
- 極端に小さい画面（CSS viewport 高650px以下）は重要情報を切ってしまわず、従来どおりスクロールを許すフォールバック。
- 背景・ノード17個と前提線16本・習得条件・SP消費・保存方式・他職のデザインを変えない。
- **ユーザーによる画面レビューまではPRをマージしない。** 承認を受けた後に改めてマージする。

### 実機確認
1. iPhone縦画面で「戻る/タイトル/SP/リセット/4タブ/せんし/紋章盤/詳細/習得する」まで1画面で見えるか。
2. 盤面が縦幅に合わせて正方形を維持し、中心紋章・17ノードが欠けないか。
3. 汎用Ⅰ～Ⅲ切替時、旧UIを破壊しないか。ほかの職・けんごうへの波及がないか。
4. 「−」「＋」「全体」「ノード選択」「習得する」「リセット」の操作は以前どおりか。
5. 小型iPhoneや文字サイズを拡大した環境では、クリップせず必要に応じてスクロール可能か。
