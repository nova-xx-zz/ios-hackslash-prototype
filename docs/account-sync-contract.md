# 正式Web → iOS アカウント・バックアップ移行（着手段階）

本PRは#67の安全な契約と**未来schema上書き防止**の第一段階。実際のログイン連携やクラウドAPI、Firebaseへのデプロイはまだ実装していない。

## 今回追加した境界

- `js/core/sync-contract.js` の`progressDto`は購入・有償石・無料キャンペーン権の項目を進行DTOから除外する純粋関数。装備・キャラの真正性は検証しない（対人/ランキングなしの既存方針）。まだ既存`js/cloud.js`からは呼ばない。
- `revisionDecision`は楽観ロックと操作IDの再送判定をモデル化したもの。実際の排他/重複排除は**サーバーのトランザクション、永続的な操作台帳**で実施する必要がある。
- `js/model/save.js` の未来スキーマ復元拒否と`js/ui/models.js`の読取専用ブロックで、古いWeb/iOSが未来版を黙って上書きするリスクを減らす。

## #67で今後実装するもの

1. 本人確認付きアカウントのリンク/再ログイン（Firebase Auth、Apple/Google等の採用決定、匿名UIDと不変accountIdの対応）。
2. HTTPS Cloud Functions APIで進行のみバックアップし、認証されたaccountIdから所有者を照合。既存の`saves/{uid}`へのクライアント直結を正式環境では使用しない。
3. バックアップexpectedRevision＋operationId＋payloadHashを**サーバー内で原子的に判定**し、競合時は409と復元確認画面を返す。
4. 正式Web版からiOSの同じaccountIdでログインし、端末/クラウドを選んで復元。旧プロトタイプの進行・無料購入は正式版に取り込まない。
5. 未来schema・未知フィールド・容量超過・ログアウト/アカウント削除・通信失敗・2タブ競合・バックアップ復旧の実機試験。

## 公開判定

現時点は#67の**部分着手**であり、アカウントの復旧/認証の安全性は未確認。Previewでは従来の直接Firebase保存を続ける。#66の本番Rulesはdeny-allであり、本番クラウド保存API完成まで正式公開しない。
