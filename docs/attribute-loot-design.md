## B. 属性の確定方針

### B-1. 属性ID・相性

属性は10種。以下のIDは**衝突防止のための提案名**（コード実装は未着手）。

| グループ | 表示名 | ID案 | 有利な相手 |
|---|---|---|---|
| 基本 | 土 | earth | 炎 |
| 基本 | 炎 | fire | 氷 |
| 基本 | 氷 | ice | 雷 |
| 基本 | 雷 | thunder | 木 |
| 基本 | 木 | wood | 土 |
| 特殊 | 龍 | dragon | 血塗られた |
| 特殊 | 血塗られた | bloodstained | 龍 |
| 特殊 | 混沌 | chaos | 金 |
| 特殊 | 金 | gold | 混沌 |
| 特殊（万能） | 虚無 | void | 他の9属性（通常時） |

- **基本循環**：土→炎→氷→雷→木→土。矢印は「攻撃する側が有利」。逆向きは不利。
- **特殊**：龍↔血塗られた、混沌↔金。それぞれ攻撃側が相手に有利。ほかの組み合わせは基本中立。
- **虚無**：通常時は他9属性への攻撃が有利。一方でダンジョン効果や敵の耐性・完全無効に左右され、虚無だけで攻略しきれないようにする。「虚無→虚無」は原則中立。
- 現行の「聖・闇」「水・風・光」ラベルからの一括自動置換は**行わない**。旧データの属性名と新10属性の対応を、敵/技単位で調査して移行表を作る。
- 武器シリーズ「虚無」と攻撃属性「虚無」、武器シリーズ「ゴールド」と攻撃属性「金」は**異なるフィールドと識別子**にする。

### B-2. 倍率と処理優先順位（初期比較値・未確定）

| 条件 | 仮の倍率 | 意図 |
|---|---:|---|
| 基本5で有利 | ×1.30 | 特化属性の価値を高める |
| 基本5で不利 | ×0.80 | 対策装備を持ち替える意味 |
| 特殊相互有利 | ×1.25 | 特殊属性の相互対策 |
| 虚無が他9属性を通常攻撃 | ×1.15 | 汎用性はあるが特化に劣る |
| 中立/同属性 | ×1.00 | 基準 |
| 特定ダンジョンで虚無活性/抑制 | 例：×1.40 / ×0.70 | **実際の最終倍率・加算順はプレイテストで確定** |
| 特定敵の虚無強耐性/無効 | 例：×0.50 / ×0.00 | 万能装備の一本化を防ぐ |

**重要：倍率表の「×1.40/×0.70」は仮の見せ方。** ドロップ・敵HP・武器ステータスと一緒に最終ダメージを検証してから、環境補正を「相性倍率の置換」か「別乗算」か統一する。無条件に全倍率を掛け算すると極端な結果を生むため、テストケースを先に決める。

### B-3. 効果判定の安全な順番（設計提案）

1. 攻撃属性を決める。通常攻撃は装備属性、技は技の明示属性優先を初期案とする（バフによる上書きは後で整理）。
2. 敵が**完全無効**なら原則0倍を返す。一般の属性反転/耐性貫通で無効を解除できない。
3. 基本/特殊/虚無の相性を取得する。
4. ダンジョン環境と敵の個別耐性を評価し、順序・重複時の上限を適用する。
5. 武器の属性反転等のOPを適用する。**不利→有利は原則指定した1属性との相性のみ**。完全無効より優先しない。
6. 最終倍率と適用理由を戦闘ログ/自動戦闘AIへ渡す。0倍しか出ない攻撃をAIが選び続けない。

実装時は属性計算だけを純粋関数化し、10×10属性表、虚無活性/抑制/完全無効、属性反転、通常攻撃/技属性の整合をテストする。

### B-4. 最初に試したい対決

| 攻撃側 → 相手 | 通常の予測 | 特別条件 |
|---|---|---|
| 炎 → 氷 | 有利 | なし |
| 炎 → 土 | 不利 | 「対土反転」OPで有利に変えられる |
| 龍 ↔ 血塗られた | 両方向で有利 | なし |
| 混沌 ↔ 金 | 両方向で有利 | なし |
| 虚無 → 炎 | 有利だが基本特化より倍率控えめ | なし |
| 虚無 → 任意属性の耐性ボス | 不利/無効になり得る | ボス固有の耐性を優先 |
| 虚無 → 虚無 | 中立 | ダンジョンの虚無補正を別途判断 |

## C. 装備収集の確定方針

### C-1. 収集の4つの価値軸

1. **武器レアリティ**：N/R/SR/UR/LR（本体の基本性能・継承先の成功率/枠数）。
2. **天然オプションのレアリティと数値**：武器レアリティとは独立。例：N武器から希少な会心OPが出る可能性を残す。
3. **属性・シリーズ・種類**：同じレア度でも有利なダンジョンとビルドが変わる。
4. **固有効果と入手場所**：固有装備・呪い/条件付きシリーズ・特殊ボスOPなど、周回目的を分散する。

収集ループ：ダンジョン周回 → 自動分解/保護の選別 → 天然OPを見極める → 必要なら抽出（武器は残る） → 上位装備の強化/穴あけ → 継承 → 対象ダンジョンで実戦比較 → 別ビルドを探索。

### C-2. シリーズ・武器名・装飾品カテゴリ

**相談で出たシリーズ候補（本体に全部実装済みという意味ではない）：**
アイアン、ブロンズ、ゴールド、プラチナ、メタル、スチール、ミスリル、ドラゴン、ホーリー、アビス、豪爆、轟混、虚なる、魔ぜる、耀妖、常闇、失墜、虚無、呪い系（血塗り/墜落/邪眼/愚かな）。

- 新シリーズをすべて通常ドロップ表に同時投入すると、1種類あたりの出現率が下がり厳選が辛くなる。**通常の地域シリーズ、ダンジョン限定シリーズ、固有/呪い系**に分けた入手設計を先に決める。
- 武器の候補：ソード、ダガー、ブレイド、ワンド/ロッド、アクス、サイス、スピア、クロー、拳銃、ボウ、素手。**素手は装備なしの戦闘スタイル**案。現行の大剣・メイス等との対応は未確定で、即削除しない。
- 装飾品は**指輪、ブレスレット、イヤリング、その他**の4カテゴリを持ち、それぞれシリーズ型と固有型を用意する。ただし**装備スロットは現行の最大3枠を維持する方向**。既存の「靴・お守り・ブローチ」を「その他」に集約する場合も、旧セーブと装備中アイテムを失わない移行が必要。

### C-3. 天然OPと穴あけの競合（要重点レビュー）

**既存の大きな矛盾：** 現行のハード/エクストラ装備は天然OPが1〜3個付く。しかし試作の設計では最大OP数がN1/R1/SR2/UR3/LR4。しかも穴あけで「後付けする枠」を解放する。

実装前の推奨（**暫定、体感前に最終確定**）：

- 天然OPはドロップ時に付く。**天然OP数＋継承OP数は武器レアリティの最大OP数を超えない**。
- 解放済みの穴の数は**後付けの継承OP数の上限**とする。例：SR+50は継承OP最大1、SR+99は最大2。ただし既存の天然OPが1つあれば、SR+99でも追加できるのは最大1つ（合計2）。
- 天然OPがある武器であっても、後付け枠を使えるまで強化/穴あけの操作が必要。不要な天然OPを抽出すれば本体の容量が空く。
- ドロップ時のOP付与数は **min(モードごとの抽選数, レアリティの最大OP数)** などで抑える。N/Rに3個の天然OPが入らないようにする。
- 天然OPを複数持つ武器からの抽出は、取り外すOPを1個選ぶ。他の天然OPと武器本体は維持。
- 継承素材は **{key, value, optionRarity, sourceItemRarity, origin, bundleId}** のように効果の実数値まで保存する。試作工房の固定OP表示だけでは実ドロップの {key,value} を失うため、必ず拡張する。
- 同じ種類のOPの重複付与を禁止。属性反転などの**特殊OPは最大1個**。強化した分の数値は上書きや品質アップで勝手に増えない。

このルールにより「SR+99の空武器にOP2個を後付けできる」という会話上の想定と、天然OPありの収集価値を両立できる。

### C-4. 継承リスクと抽出液

| 継承先 | 継承元のレア度 | 通常継承成功率 | 天井 | 最大OP総数（暫定） |
|---|---|---:|---|---:|
| N | なし | — | — | 天然1 |
| R | N | 100% | 不要 | 1 |
| SR | N・R | 100% | 不要 | 2 |
| UR | N・R・SR | 65% | 2失敗→次回確定 | 3 |
| LR | N・R・SR・UR | 45% | 3失敗→次回確定 | 4 |

- 下位から上位への直接継承可。Nの希少OPが最終装備の素材になり、N収集が腐りにくい。
- 抽出は100%成功、武器本体は消えない。天然OPだけを取り外す。**継承済みOPは再抽出不可**。
- 抽出液の個数はOPランクで N=1/R=2/SR=3/UR=5/LR=8（暫定）。1抽出→1継承分の束であり、増殖不可。
- 試行失敗時は液体を消費して武器・既存OP・穴は維持。
- 確定継承液はUR/LRで1回の継承を100%成功にする課金候補。**試作の無料テスト配布は商用の無料入手ルールを意味しない**。
- 課金液使用の成功では既存天井カウントを変更しない。天井到達時に確定液を使用させない。

### C-5. 掘り続ける理由を作るドロップの分離（提案）

| 周回先 | 狙うもの | 調整ポイント |
|---|---|---|
| 通常の進行ダンジョン | 現レベルに合った武器本体・シリーズ | 進行を止めない、序盤から選ぶ楽しさ |
| ハード/エクストラ | 高品質な天然OPの付いた武器 | 現行ルールとの整合、Nでも良OPを掘れる条件 |
| 属性特化ダンジョン | 属性シリーズ、反転など希少な天然OP | ボス耐性と収集需要を結び付ける |
| 特殊/期間限定ボス | 固有武器、希少な対策OP | 他装備の価値を無効化せず、新しい目標を追加 |

**自動分解の注意**：現在の自動分解は主にレア度ベースなので、N装備を自動分解すると希少OPも失われる。天然の高レアOP/特殊OPがある武器は保護するフィルタを、入手バランス調整と同時に設計する。

**ドロップ供給の注意**：虚無武器や属性反転OPが常に低レベル通常ダンジョンで出ると、属性対策の価値が落ちる。出現率・ダンジョン条件・OPランク・序盤の戦闘バランスを分けて設計する。

## D. 次のプロトタイプ検証順（実装はこれから）

1. **属性データの独立設計**：10種のキー、相性解決関数、敵耐性、ダンジョン環境、技/通常攻撃の属性を整理。旧「聖・闇・水・風・光」をどのように残す/移行するか一覧化。
2. **ドロップとOPデータの整合**：天然OPの最大数、希少OP出現条件、抽出液へ引き継ぐ {key,value,rank}、自動分解の保護条件をテスト。
3. **代表3ビルドで比較**：(a)虚無中心の汎用装備、(b)基本属性の特化、(c)属性反転OP入りの対策装備。通常/虚無抑制/虚無無効の3ダンジョン条件で比較。
4. **数値バランスの調整**：1周の所要時間、狙いのOPが出るまでの周回、UR/LR継承に必要な抽出液の消費、装備持ち替えの意味を確認する。
5. **本体へ段階適用**：セーブ互換・装備制限・戦闘AI・既存ジョブ/敵の回帰検証を通してから、実ゲームで操作テストする。

## F. 属性と装備収集の詳細設計・セルフレビュー（2026-10-13、追加提案）

> ここは**検証する具体案**。従来合意した10属性・抽出時に元武器を残す・UR/LRの成功率と天井・SR+50/+99の開放条件は変更しない。下記の新しい例外／仕様調整はプレイテスト後に採否を決める。戦闘コード・報酬コードの挙動はまだ変更していない。

### F-1. 天然OP、継承OP、穴の役割を混同しない

**推奨：武器の総OP上限は N=1 / R=1 / SR=2 / UR=3 / LR=4。天然OPも合算して上限を数える。**

| SR武器の例 | 天然OP数 | 継承OP数 | 合計 | 次に必要な操作 |
|---|---:|---:|---:|---|
| 天然なし、+0 | 0 | 0 | 0/2 | +50まで強化→1穴あけ |
| 天然なし、+50・1穴 | 0 | 1 | 1/2 | +99まで強化→2穴目をあける |
| 天然なし、+99・2穴 | 0 | 2 | 2/2 | 完成 |
| 天然ATK+5%、+50・1穴 | 1 | 1 | 2/2 | ここで満枠。+99にしても天然を抽出するまでは2穴目は開けられない |
| 天然2個（旧エクストラ由来） | 2 | 0 | 2/2 | 既存セーブを破壊せず、天然の抽出と穴あけを行う |

- **今後のドロップは原則「天然OP最大1個」**を比較候補とする。現在のハード1〜2個／エクストラ2〜3個をそのまま利用するとN/Rの1枠上限を超えるので変更が必要。モード差は天然OPの**品質（レア度・数値・入手条件）**で出す案。
- 天然OPはドロップ時から効果が有効。穴あけは継承OP専用で、**天然OP + 継承OP <= 総OP上限**。穴あけの必要+値は変えない。
- +値到達は「穴あけ可能段階」の解禁であり自動穴あけしない。満枠なら素材を消費して穴あけをさせず、天然OP抽出後に残った解禁段階から穴を開けられるようにする。
- 既存のOP2〜3個付きアイテムは新コード適用時に黙って切り捨てない。新規生成ルールと**旧セーブ移行**を別に扱う。
- 属性付き武器とOPの情報は別フィールド：例 {rarity:"sr", attackElement:"fire", series:"gold", options:[{key:"atk_pct",value:0.05,rank:"r",origin:"natural"}], sockets:{opened:1}, transferPity:{...}}。固定効果・シリーズ効果は合成OP数に含めず、重複上限は別途決める。

**設計上のトレードオフ**：天然1個を持つSR武器は+50段階で既に2効果を完成できる。+99で2つの新規継承枠が常に増えるわけではない。「SR+99なら必ず2回継承可能」よりも「最大2OP」を優先する案。+99には通常のステータス強化価値が残るが、試遊でこの不満が大きければ総枠／天然枠の分類を再検討する。

### F-2. 継承の制限、天井の抜け道

- 同じ部位の継承を基本にする（**武器→武器は剣/短剣などの種類を問わず可**）。異なる部位／アクセサリーへの継承はオプション適合ルールを別途検証。
- 下位の**武器レアリティ**から上位の武器レアリティへの直接継承。OPランクは元武器のランクと独立し、OPの {key,value,rank} の**実数値・数値精度**をそのまま運ぶ。
- 現試作は天井を継承先武器だけで管理。例：希少OPを継承する前に安価なN-OPでURを2回失敗させる→3回目に希少OPを確定継承できる。この方法では確定継承液の価値が下がり、周回設計も崩れる。
- **対策の提案**：天井進捗を「継承先武器ID × OP効果キー × OPランク」で分ける。同じ種類/ランクのOPを失敗した場合だけ加算。同ランク内の極端な数値差・希少OPを別扱いする必要があれば、OPの品質帯もキーに追加する。全OP共通天井より複雑なため、残り失敗回数を確認できる表示を設ける。
- 通常継承が成功すれば**そのOPの天井だけ**リセット。確定継承液を使った時はカウントを消さない。天井到達時は課金液を使用させない。
- 成功率と天井の初期設定はUR65%・2失敗で次回確定、LR45%・3失敗で次回確定を維持。各試行で同じOP素材を再取得できるなら、必要試行回数の期待値はUR約**1.47回**、LR約**2.02回**（天井を含む。成功までの1回目から数える）。確定液の価値は、消滅するOPの**希少性**・周回コスト・再抽出難度から評価する。

### F-3. 抽出液の「個数」に意味を持たせる

現在の試作はOP抽出時に N1/R2/SR3/UR5/LR8 個の液体を**ひと束**として生成し、成功/失敗いずれでも同じひと束を消費する。**抽出数が違っても継承可能回数は常に1回**なので、個数だけではゲーム経済上の差にならない。

**推奨する試作追加案**：
- 抽出液の束は正確なOP（効果キー・数値・ランク・出所）を1回だけ継承できる単位で保存。分割・複製しない。
- 束を精製して継承する際、OPランクごとに別のゲーム内素材「精製触媒（仮）」を **N1/R2/SR3/UR5/LR8個** 消費させる。抽出液の数量と必要精製触媒を対応させることで、レアOPの調合コストに実質的な差が生まれる。試遊では触媒を模擬配布。
- 触媒は通常周回で獲得、**確定継承液の購入とは別**。確定液はUR/LRの成功率を100%にするだけでOPや触媒を生み出さない。
- 継承成功/失敗ともOPの束を消費する。素材を追加しても1個の天然OPが2個に増えることはない。
- 触媒による必要素材数が収集の負担を増やしすぎる場合は、数量差を表示上に留めるのではなく、**レアOPの精製コストを小さくするか、別の実利用先を決める**。

### F-4. 属性と武器・技の優先関係

| 条件 | 攻撃属性の提案 |
|---|---|
| 属性を明示した技 | 技の属性が最優先。武器の属性と二重に倍率をかけない |
| 属性指定のない物理技・通常攻撃 | 一時的な属性付与があればそれを優先し、なければ装備武器の攻撃属性 |
| 属性指定のない魔法 | 原則は無属性。明示的な属性付与魔法の場合だけ付与属性を適用する案 |
| 素手 | 無属性（スキルの属性がある場合を除く） |
| 二刀流 | 最初は右手武器基準、将来各武器のヒットにそれぞれの属性を持たせることを検討 |

- 同一武器のシリーズ名「虚無」と攻撃属性 void は別フィールド。シリーズ名から属性を推測しない。
- 相性（×1.30、×0.80、虚無×1.15など）は**純粋関数**で解決し、敵固有耐性・ダンジョン環境・OP補正・無効判定を分離する。
- 属性反転「対土」なら、例えば炎→土の×0.80だけを×1.30に変更する。炎→氷の元から有利な判定や、そもそも完全無効の敵には影響しない。
- 虚無の例として「通常 ×1.15」「虚無抑制の環境係数 ×0.70」「虚無活性の環境係数 ×1.40」を比較。ただしダンジョン係数と敵耐性の乗算順・上限・特別な免疫を統一し、極端な重複補正を防ぐ。虚無無効を0倍で返す仕組みを最優先する。

**重要な実装上の注意**：現行 js/core/battle.js の倍率判定は res.el[element] の真偽値を確認しており、**0を「指定なし」と見なしてしまう**。今回の「完全無効」を実装する前に、0が正しく0倍扱いされる判定へ変更し、expectedHitDamage・戦闘AI・ダメージ計算・オフライン進行を揃える必要がある。

### F-5. 比較テストに使う「3ビルド × 3ダンジョン」

| 武器ビルド | 通常の土属性の敵 | 虚無抑制ダンジョンの土敵 | 虚無無効の土ボス |
|---|---|---|---|
| 木属性の特化装備 | ×1.30（基本有利） | ×1.30 | ×1.30 |
| 炎属性＋「対土反転」 | ×1.30（元は不利×0.80） | ×1.30 | ×1.30 |
| 虚無属性の汎用装備 | ×1.15 | 仮：1.15×0.70＝×0.805 | **×0** |

> この表は属性倍率のみ。攻撃力・技能倍率・ボス防御力などの違いは別途反映。虚無無効の土ボスは例示で、具体的な敵配置を確定したものではない。

目的は、虚無が万能一択でないだけでなく、**木属性専用装備**と**反転OPで弱点をカバーした炎属性装備**の両方が使われること。反転が何でも強い最適OPとならないよう、特殊OP最大1枠を維持。

### F-6. 集め続ける理由と自動分解保護

| ドロップの役割 | 例 | 収集価値 |
|---|---|---|
| 通常シリーズ武器 | ブロンズ、アイアン、スチール、ミスリル等 | キャラの装備更新とセット効果 |
| 属性特化シリーズ | 新設の限定シリーズ等 | 特定ダンジョンのボス対策 |
| 天然OP素材武器 | Nの会心OP、Rの属性増幅OP等 | 装備本体が低レアでも抽出素材として必要 |
| 固有・呪い・特殊ボスドロップ | 虚無/龍・血塗られた関連の固有効果等 | キャラ別の最終ビルドとコレクション |

- 現行 js/core/rewards.js の自動分解はレア度・unique・lockedを主に参照し、**天然OPの希少性を判定しない**。新OPテーブル導入時は「SR以上の天然OPを持つ装備」「特殊OPを持つ装備」などを自動分解から保護する初期設定を検討（種類は要バランス調整）。
- 属性/OPの入手確率の掛け算を検証する。例えば1ドロップが「N武器で、ある特定の天然OPを持つ」確率を仮に0.0781%とすると、8ドロップ/周なら期待約160周で1本。**この数値はドロップ統計から求めた実測ではなく、仕様検討用の単純例**であり、入手率を設定するときは段階別・対象アイテム別に計算する。
- 属性特化ダンジョン、通常ダンジョン、ボスごとのドロップ目的は分けるが、新シリーズを一度に全部投入しない。既存の職業装備制限や装飾品スロット最大3を踏まえて追加する。
- 装備保存形は「アイテムID」「武器レアリティ」「属性」「シリーズ」「天然/継承OPの識別」「OP数値・OPランク」「解放済みスロット」「OP別の天井進捗」を分ける。

### F-7. 次に試作する最小範囲

1. 属性10種の**読み取り専用比較ロジック**と120例程度（10×10基本相性＋ダンジョン/敵例外＋属性反転）の自動テスト。既存ゲームの戦闘を突然置き換えない。
2. 天然OPと継承OPの枠管理を、R/SR/UR/LRと旧OP複数付与アイテムで検証。別データでの互換性テストを先に作る。
3. 天井の「同一OP・同一ランクのみ通算」と抽出液の触媒コストを**試作工房で先に体感**。正式課金商品はまだ変更しない。
4. 属性別3ビルドで、通常・抑制・完全無効のダンジョン条件を比較。平均周回時間と武器の使い分けを測り、倍率を決める。
5. 自動分解保護・OP数値の保存・端末セーブ互換を確認後、限定ダンジョンから本体に段階的に統合する。

**ユーザー合意前の保留**：天井をOP別に切り分ける案、天然OP最大1個の案、抽出時の触媒コスト、武器属性の技への反映ルール、各ドロップ確率。試作で検証してから確定する。
