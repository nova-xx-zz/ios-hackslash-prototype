# 実ゲームデータでのOP重複上限・セルフRV

更新日: 2026-10-14

> **結論：前回の上限案はまだ戦闘本体へ適用しない。** 実際の職業・種族・技・スキルツリー・装備シリーズを通すと、装備OPが0個でも吸収上限に達する構成があり、会心・回復・MP軽減は低いOP数でも上限が働く。既存育成の価値を損なう恐れがある。

## 計算元・再現方法

- `node tools/audit-option-caps.js` で表を再生成できる。自動テスト: `tests/real-option-cap-audit.test.js`。
- 生データ: `js/data.js`（JOBS, RACES, EXCLUSIVE_TREES, GENERAL_TREES, GENERAL_SLOTS, JOB_EQUIP, ITEM_SERIES, ITEM_BASES）と `js/options.js`（ITEM_OPTIONS, itemOptionEffect）。`tools/lib/load-data.js` を通して **実ファイルを実行時に読む**。試作向けに数値を再入力しない。
- `tools/lib/real-option-cap-audit.js`：スキル前提ノード・分岐排他・スキル取得Lv・Lv99でSP98まで、汎用ツリーは各スロット許可候補のみ、装飾品3枠を解放する2ノード分のSP消費、職業の武器/頭/胴装備適性、6点セットの実在を検証する。
- 装備は実在する同一シリーズの **武器・頭・胴・装飾品3種（6部位）**を使用。全6部位それぞれに「Extraの現行OP範囲の最高値」を1個だけ積む **厳選が極端に成功した上限ストレスケース**を比較する。OP0、2、6個（セット6点は固定）を並べる。
- `js/core/equipment.js` の `setBonusTotals` と、OPのpassive効果・6点セットの合算が一致することをテストする。上限前後は以前作った独立 `option-stack-trial.js` を使用。
- **実際のプレイヤーの獲得装備ではない**。実際の6点入手確率、強化・継承成功率、職業・種族の解放条件、確率ドロップ、パーティ全体ボーナスやダメージ倍率の継続時間までは再現しない。全ジョブ・全分岐を網羅した数学的最大値でもない。

## 結果（実データ使用・数値は1桁に四捨五入）

以下は各ケースの **「上限前 → 暫定上限を掛けた後」**。OP2は対象OPを2部位、OP6は6部位に最高値で付ける。ジョブ・スキルの効果は同じまま比較する。

| ビルド | 職業・種族 | シリーズ | SP / 98 | OP0 | OP2 | OP6 |
|---|---|---|---:|---|---|---|
| 会心特化 | 忍者・ハーフビースト | アビス6点 | 51 | 68.0 → 68.0% | **84.0 → 75.0%** | 116.0 → 75.0% |
| HP吸収特化 | 暗黒騎士・よあるきぞく | ドラゴン6点 | 39 | **99.0 → 80.0%** | 111.0 → 80.0% | 135.0 → 80.0% |
| 被ダメ軽減特化 | 戦士・きょじん | ホーリー6点 | 39 | 38.1 → 38.1% | 47.6 → 47.6% | 62.5 → 60.0% |
| 回復特化 | 大神官・せいれいぞく | シルバー6点 | 31 | 94.0 → 94.0% | **134.0 → 100.0%** | 214.0 → 100.0% |
| 強化石特化 | 盗賊・ヒトゾク | スチール6点 | 12 | 0.0 → 0.0% | 40.0 → 40.0% | 120.0 → 50.0% |
| EXP特化 | 僧侶・もりびと | シルバー6点 | 12 | 0.0 → 0.0% | 40.0 → 40.0% | 120.0 → 50.0% |
| MP軽減特化 | 魔法使い・こうじん | ミスリル6点 | 45 | 50.7 → 50.7% | **64.4 → 60.0%** | 81.4 → 60.0% |

## 設計レビューで見えた問題

1. **会心率75%上限は早く到達する**。実際の忍者の固有・汎用ツリー＋種族＋アビスセットでは、最高値会心OPが2個で上限に到達。さらに良い装備を集めてもその効果がゼロになり、希少OPの収集価値が薄れる。
2. **暗黒騎士の吸命を弱める可能性**。現行技60%＋パッシブ合計39%の実現可能な構成では、OPなしで技込みHP吸収99%。提案した通常30%/技込み80%上限を導入すると装備OPがなくても吸収が失われる。
3. **回復・MP軽減も2個で上限到達**。一つひとつのOPは強すぎなくても、種族やシリーズ・スキルツリーによる累積が大きい。
4. **被ダメ軽減60%は比較的機能する**。6部位すべてに最高値軽減OPという厳選に成功した例で初めて上限に達するため、他3種ほど装備厳選を阻害しない。ただし別の職・特殊ジョブ、ソロ周回時は別途評価する。
5. **強化石・EXP +50%を一律にすると、繰り返し周回の収集価値に影響する**。Extra最高値+20%のOPを2個なら上限内だが、3個で超過。パーティ複数人分を加算する現行報酬処理との結合テストが必要。

## おすすめの次の調整順

- **正式戦闘へのキャップ適用は保留**し、先に「上限到達後のOPが無価値になるか」を数値で評価する。会心は75%ハード上限を維持するか、85～90%まで許容するか、一定値以降に減衰させるかを比較。
- 吸収は **技固有とパッシブの2段階上限**を再検討。現在の暗黒騎士の技や吸収スキルを意図せず弱体化する値は原則避け、吸収量/ターン・ヒット数・攻撃対象数も考慮する。
- 回復+100%、MP60%、強化石/EXP+50%は上限に早く達するため、まず**逓減型（ソフトキャップ）**も比較。すべての追加OPの価値が突然ゼロにならない方式を候補にする。
- 実戦の期待会心ダメージ計算、実会心、回復・吸収、オフライン報酬が一貫した上限式に統一されるまでは、`battle.js` や `js/model/run.js` は変更しない。
- **次の検証を実施済み**：現行7ビルドのハード上限とソフトA/Bを同じ実データで比較（[実データ・ソフトキャップ比較](soft-cap-real-data-comparison.md)）。追加OPの価値は残るが暗黒騎士の吸収技弱体化が続く。次は技固有の吸収・報酬計算の確認 → 多職・全パーティ条件の回帰試算 → 本体段階統合（セーブ互換・全体テスト・実機確認）。

## セルフRVゲート

- データ定義から計算していること（手動でランク/技効果を複製しない）。
- スキル前提・排他・汎用スロット候補・取得Lv・SP上限・装飾品枠・装備種別の合法性。
- `setBonusTotals` のセット効果/OP合算との一致（実装名の変更/未定義API検出）。
- 同一入力の結果が変わらず、実所持品・実戦・出荷物に試作コードを混入させないこと。
