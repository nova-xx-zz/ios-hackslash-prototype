## 1. 概要

**ソードクレスト（Sword Crest）**（2026-10-05 に「クエストパーティ」から改名。タイトルは仮決定で、商標・同名アプリの確認後に確定する） は、iPhone（Safari）で遊べる、5人パーティ・オート戦闘のハクスラ系ダンジョンクロールのプロトタイプである。ビルド不要のバニラ HTML/CSS/JavaScript で実装され、GitHub Pages 上の静的サイトとして配信される。

プレイヤーは「種族×ジョブ」で構成したキャラクターのロスターを育て、最大4チーム（各5人）に編成し、I〜IVの4チームを同時にダンジョンへ出撃させられる。戦闘は完全オートで進行し、プレイヤーは事前にスキルのON/OFF・優先度・ターゲット方針・装備・転職などのビルドを整えることでダンジョン攻略を有利に進める、いわゆる「放置ゲーム／半オートRPG」に分類される体験を提供する。

> 特定タイトルの仕様を模倣したものではなく、「5人パーティ／速度依存のオート戦闘／転職システム」というジャンル共通の要素を、オリジナルの名称・データで実装したものである。ジャンルやゲームシステム自体は著作権の対象ではないが、固有名詞・グラフィック・文章表現は独自のものとする。参考にする既存タイトルのスクリーンショット等は、レイアウトの一般的な構成（例: タイトル画面の中央ロゴ＋下部CTAボタン）のみを参考にし、配色・書体・装飾・具体的なテキストは独自に作成する。

### 開発経緯

- v1: リアルタイム自動戦闘のプロトタイプ
- v2: ドラクエ/FF風のコマンド選択ATBバトル
- v3（現行）: 「速度ステータスに応じて行動間隔が変わる、5人フルオートのハクスラ」という要望に合わせて戦闘エンジンを再設計

## 3. 機能要件

### 3.1 タイトル画面
- ギルドの机に置かれた剣＋紋章のオリジナル背景。上部に金色2段ロゴ `SWORD / CREST` と和名を重ねる
- 下部の `Tap to Start` またはメニュー以外の画面タップで探索画面（プレイ中のホーム）へ遷移
- 右上に手紙型のお知らせとバージョン。下部に「設定/お知らせ」「データ保存」「データ復元」を配置し、既存の設定・クラウドバックアップ・復元確認へ接続する
- セーフエリアと小型端末に対応し、OSの「視差効果を減らす」設定では背景・開始ボタンの明滅を停止する
- 編成／探索／図鑑／設定の常設ナビゲーションは探索画面に配置
- 踏破数・所持なかま数を開始ボタンの下に控えめに表示

### 3.2 キャラクター・種族・ジョブ
- キャラクターのステータスは「種族×ジョブ」の組み合わせで決定する
- **種族**: プレイヤー用8種（ヒトゾク/ハーフビースト/もりびと/いわびと/よあるきぞく/こうじん/せいれいぞく/きょじん）＋テイム対象のモンスター37種（スライム族/ゴブリン族/コウモリ族/ウルフ族と、7地方に5〜6種ずつ。§3.9）
- 各種族はステータス倍率に加えて、会心率・被ダメ軽減・吸収・経験値倍率・MP消費減・回復量増のいずれか1つのパッシブ特性を持つ
- **ジョブ**: 基本職6種（せんし/まほうつかい/そうりょ/とうぞく/ぶとうか/あんこくし）＋上級職6種（けんごう/だいまどうし/だいしんかん/にんじゃ/けんせい/しにがみ）の計12種
- 上級職は対応する基本職をLv.50まで極めると転職可能になる
- **転職してもレベルは失われない**。キャラはジョブごとに独立したレベル/EXPを持ち、転職すると新ジョブは（未経験なら）Lv.1から始まるが、過去に極めたジョブへはそのときのレベルからすぐ再開できる
- テイムしたモンスターは人間のジョブへ転職できず、種族専用のジョブ・技を持つ

### 3.3 パーティ編成
- 所持キャラ全員は「ロスター」に属し、I〜IVの4チーム（各最大5人）または「控え」に振り分けられる
- **I〜IVの4チームは常時並行して探索できる**。探索画面のチームタブは「表示中のチームを切り替える」ためのものであり、表示していないチームも裏側でダンジョン探索を継続する
- パーティ一覧はチームごとの折りたたみ行形式。メンバーカードの長押しドラッグで別チーム／控えへ移動できる。探索中のチームはバッジで示され、そのチームの編成（メンバーの追加・削除）はドラッグ・詳細画面のいずれからも変更できない（探索を終えると再び変更可能になる）
- メンバーカードをタップするとキャラ詳細画面（能力値／装備／スキル／ジョブの4タブ、テイムモンスターは「ジョブ」の代わりに「合成」タブ）が開く。探索中のチームに所属するキャラの詳細画面は、装備・スキル・転職・合成などの変更を一切受け付けない読み取り専用表示になる（戦闘中のステータスが不整合になるのを防ぐため）

### 3.4 キャラクター作成
- 「仲間を探す」からキャラ作成画面へ遷移し、名前・種族・ジョブを指定して新規仲間を1人作成できる
- 種族・ジョブ選択は詳細モーダル（アイコン・説明・能力値の星評価・アビリティ一覧、候補の切り替え）で行う
- ランダム生成（名前・種族・ジョブを一括で振り直す）に対応
- 新しく作成した仲間は既存メンバーのレベルに関わらず常にLv.1から開始する

### 3.5 スキル・AI設定
- 各キャラはジョブ由来のアクティブ技4つ（Lv.1/5/10/15で習得）と、種族由来のパッシブ特性を持つ
- アクティブ技はON/OFF切り替え可能。OFFの技はオート戦闘AIが選択しない
- アクティブ技には優先度（優先／通常／温存の3段階）を設定でき、AIの技選択に反映される
- 攻撃対象の優先度（弱い敵から／強い敵から／ランダム）をキャラごとに設定できる
- サブアビリティ2枠: 実際にレベルを上げたことがある他ジョブの技を装備できる

### 3.6 装備・強化
- 装備枠は**右手・左手・頭・体・装飾品①〜③**の7枠。アイテムの部位は武器／盾／頭／体／装飾品の5種類
- 武器・盾・頭・体はジョブごとに装備できる種類が決まっている（例: まほうつかいは杖・ロッド・短剣と帽子・ローブのみ）。二刀流のジョブは左手にも片手武器を持て、両手武器を持つ間は左手を使えない
- 装飾品は最初1枠。スキルツリーのノードで最大3枠まで増える（モンスターはLv20・Lv40で1枠ずつ増える）
- 装備は「種類（26種）×シリーズ（ブロンズ〜アビスの8段階）」の208種＋名のある装備203種（呪われた装備を含む）。1つの装備が複数の能力値を持てる
- 同じシリーズを2・4・6個付けるとセット効果、名のある装備は固有の特殊効果を持つ。ハード・エクストラモードで落ちた装備はオプション効果を1〜3個持つ
- 装備のレベルは拾ったダンジョンの推奨Lv（モード込み）で、能力値は1Lvごとに基礎値の+12%伸びる
- 転職・スキルの振り直し・装飾品の枠数の変化で装備できなくなったアイテムは所持品に戻す
- 旧セーブの3枠（武器／防具／装飾品）・単一能力値の装備は、読み込み時に新しい枠・種類へ移す（詳細設計§1.2）
- 所持品（インベントリ）は全チーム共有
- 「おまかせ装備」でジョブの基礎値を重みにした自動選択が可能
- 装備は個別に+0〜+99の強化値を持ち、強化石を消費して強化に挑戦できる（成功率はレア度が高いほど・+が高いほど下がる、下限あり）

### 3.7 ダンジョン探索
- 探索画面はタイトルに合わせた青緑・古金色のギルド背景とする。待機時には出発案内、探索中・帰還後には高い不透明度のログカードを表示する
- 未出発かつログのないパーティでは「マップを開く」、未編成なら「仲間を編成する」を案内する。既存のマップ／編成画面へ進み、案内ボタンだけで即出撃はしない
- 仲間カードの職業紋章と下部ナビゲーションは線画で統一し、HP・MP・レア度の色は判別性を保つ。小型画面では案内のスクロールと職業紋章の省略で操作領域を確保する
- 7地方・35ダンジョン（推奨Lv1〜100）。地方ごとのマップに配置され、クリアすると次のダンジョンが、地方の最後を踏破すると次の地方が解放される
- 各ダンジョンにノーマル／ハード（推奨Lv+10相当・EXP1.5倍）／エクストラ（同+25相当・EXP2倍）の3モードがある。ハードはそのダンジョンのノーマル踏破、エクストラはハード踏破で解放し、モードごとに踏破状態を記録する
- 1ダンジョンは3〜5回の連戦＋最後は強化ボス戦。戦闘は完全自動進行。ボス戦以外ではまれにレア敵が出現し、高レア度の装備を落とす
- ダンジョン入場時にHP/MPは全回復し、道中の戦闘では持ち越される
- 戦闘間に約6割の確率で道中イベント（宝箱／罠／泉／石碑）が発生する
- 全滅した場合はそのダンジョンは失敗となり、HPは自動回復。再出撃または別ダンジョンへの移動が可能

### 3.8 ドロップ・レア度・自動分解
- 敵撃破でEXP・装備ドロップを獲得。レア度はN/R/SR/UR/LRの5段階（出現比率は概ね71%/22%/6.5%/0.35%/0.15%）
- **ドロップはダンジョンを踏破して初めて確定する**。道中で見つけたアイテムは一旦保留され、踏破時に所持品化（または自動分解）される。**全滅した場合はその周回で見つけたドロップを一切持ち帰れない**
- 自動分解機能: ONにすると対象レア度のドロップをその場で強化石に変換する。対象レア度はチップ（N/R/SR/UR/LR表記）でフィルター可能
- 自動分解のON/OFF・フィルターは出撃中のチームがあってもいつでも変更できる。出撃した瞬間の設定値がその周回にスナップショットとして固定されるため、途中で設定を変えても進行中の周回の結果には影響しない

### 3.9 モンスターのテイム・合成
- ダンジョンクリア後、道中で倒したテイム可能な敵から1体を選んで成功判定を行い、成功すればロスターに加わる
- テイム可能なのは種族専用ジョブが用意されている37種（スライム/ゴブリン/コウモリ/ウルフ＋7地方に5〜6種ずつ）。テイムしたモンスターはどのダンジョン・モードでもLv1から仲間になる
- テイムしたモンスターはお気に入り（★）に登録できる
- **モンスター合成**: テイムしたモンスターの詳細画面「合成」タブから、控えの他モンスターを素材として選び合成できる。素材は消滅し（装備していたアイテムは所持品に戻る）、素材1体につき「種族の基本EXP＋素材が積み上げたEXPの半分」が対象モンスターに還元される（同じ種族の素材は1.5倍）。チーム編成中・お気に入りのモンスターは素材候補から除外される。すべて／種族ごとにまとめて選べる

### 3.10 モンスター図鑑
- 全200種のモンスターを収録。未遭遇のモンスターは「？？？」表示で隠され、戦闘で遭遇すると図鑑に登録される
- 登録済みモンスターはアイコン・属性・テイム可否・説明文・ステータスを確認できる
- 発見状況は端末に保存され、次回起動時も引き継がれる

### 3.11 自動周回・オフライン進行
- **自動周回**: チームごとに独立して、直前に挑んだダンジョンへ指定回数（x1/x3/x5/x10/x20/x50）だけ自動で再出撃し続ける機能。全滅時は自動的に停止する安全装置を備える。複数チームが同時に自動周回することもできる
- 稼働中のチームは、そのチームの編成・出撃先ダンジョンの変更のみロックする。他チームの操作・自動分解の設定変更は妨げない
- **自動周回のオフライン進行**: 自動周回が稼働中の状態でアプリを離れる（タブを閉じる/バックグラウンドに回す）と離れた時刻を記録し、次回起動時（またはバックグラウンドからの復帰時）に、経過時間（最大8時間、超過分は切り捨て）の範囲で通常プレイと同じ戦闘エンジンで1周ずつ戦わせ、チームごとに独立して結果を一括反映する。通常プレイとは石碑の加護の省略などの差があり、完全に同じ結果は保証しない（詳細設計§2.11）。自動周回は出撃したモードのまま精算する。複数チームが同時にオフライン進行していた場合は、結果もチームごとに分けて報告する。オフライン中も全滅が起こり得て、全滅した周はドロップ・テイムを持ち帰れず自動周回も停止する。EXPは通常プレイと同じく勝利した戦闘ごとに付与し、全滅した周でもそれまでの勝利ぶんは残す。遭遇した敵は図鑑に登録し、道中の宝箱ドロップも計算に含める
- 精算した報酬と自動周回の停止は1回の保存で確定し、保存に失敗しても報酬が二重になったり失われたりしない（保存できないまま終了した場合は次回起動時に同じ期間を精算し直す。詳細設計§2.11）

### 3.12 セーブ・ロード
- 所持キャラ全員（レベル・ジョブ・種族・装備・スキル設定等）・所持品・強化石・出撃中チーム・モード別のクリア済みダンジョン・冒険の記録を端末（localStorage）のメインセーブ1件に保存する（強化石はメインセーブが正本で、旧 `jobquest_material` キーは互換用のミラー）
- 端末への保存のたびに、Firebaseの匿名ログインでFirestoreへバックアップする（最短1分おき・離脱時は即送信）。設定画面からクラウドのセーブで復元できる。匿名ユーザーは端末ごとに別で、別端末への引き継ぎ（アカウント連携）は未対応
- 保存タイミング: キャラ詳細/編成操作時の遅延保存、ダンジョンクリア/全滅時の即時保存、タブを閉じる/バックグラウンド化時、20秒ごとの定期保存
- 保存に失敗した場合（容量超過など）はゲーム進行を止めず、画面上部の警告で知らせる
- 保存データが無い場合（初回起動）のみ、Lv.1の5人スターターパーティから開始する

### 3.13 自動戦闘AI
- ON状態かつレベルで習得済み、MPが足りるアビリティのうち、回復技は「単体回復なら誰かのHPが80%未満、全体回復なら70%未満の時だけ」候補に入る
- 最も優先度の高い技のグループに絞り（通常の優先度では通常攻撃も比較に入れる）、その中で期待効果（見積もった与ダメージ・回復量）が最大の技を使う。同値なら消費MPが少ない方（詳細設計§2.8）


### 3.14 スキルツリー（第1弾「標準ツリー＋SP」・第1.5弾「固有＋汎用3枠・分岐図UI」は実装済み。ブックによる汎用枠の交換は採用済み・未実装）
- 実装済み: 1キャラは「固有ツリー（ジョブの系統タグ＝せんし/けんごう＝warrior等、6系統ごとに固定1本、交換不可）」＋「汎用ツリー3枠（全ジョブ共通のツリープールから、枠ごとに決まった2択で交換可能）」の計4本を同時に持つ。レベルアップで得るSP（`Lv-1`）は4本で共有する1つのプールから消費し、パッシブ／アクティブ（固有ツリーのみ）のノードを習得する。前提ノード・排他分岐（同グループ内は二者択一）を各ツリーに備える
- 実装済み: ツリーは実際に分岐する図（ノードを線で結んだ、本物のスキルツリー然としたUI）で表示する。ノードをタップすると詳細（説明・コスト・習得状況）が開き、そこから習得を確定する
- 実装済み: 汎用ツリー3枠は、枠ごとに決められた交換候補2種の間でいつでも交換できる（探索中／自動周回中のチームのみロック）。交換すると、その枠に振ったSPだけリセットされ、固有ツリー・他の枠のSP配分には影響しない
- **採用済み・未実装**: 上記の枠交換をスキルブックの入手（ドロップ）・鑑定所での鑑定・所持品からの消費と結びつけること。現状の交換は無償・即時の簡易実装であり、ブック経済実装後はそちらに置き換える
- ツリーで取得した技も既存のON/OFF・優先度・ターゲット方針を利用する（実装済み）。ジョブ固有技・サブアビリティ2枠は維持し、ツリー効果との重複ルールは詳細設計§6.2のとおり加算系／乗算系で区別して実装した
- 探索中／自動周回中のチームに所属するキャラのツリー変更・SP操作・枠交換は禁止する（実装済み、`isTeamLocked`で判定）。他チーム・控えへの操作は妨げない
- SPの獲得量・上限・ノード数・排他分岐・（ブック導入後の）振り直し費用は引き続き調整事項。現行の数値は初期実装のための仮値

### 3.15 スキルブック・鑑定所（採用済み・未実装）
- ダンジョンで未鑑定スキルブックを入手し、鑑定所で**強化石**を消費して鑑定する。レア度は装備と同じN/R/SR/UR/LRの5段階
- 未鑑定時に判明するのはレア度。ツリー名・内容・使用可能ジョブは「？？？」とする。鑑定費用はレア度に応じて事前に表示する
- 鑑定するとツリー名・内容・対応ジョブが判明する。鑑定では本を消費・適用せず、鑑定済みの本として全チーム共有の所持品に保管できる。複数冊のストックを認める
- 使用時に対象キャラへツリーを適用して1冊消費する。別のツリーへ変更し、後で元のツリーへ戻す場合も、元の本を再び1冊消費する
- 使用可否は**ジョブ系統タグ＋ツリーごとの適性**で判定する。完全な全職共通にも、個別ジョブ名への固定にもせず、基本職の対応範囲を広く、上級職は専門性に応じて絞る
- 高レアほどツリーの完成度・シナジー・希少な効果・独自の戦い方を充実させる。単なる倍率の上昇にせず、低レアの安定型・特化型が適する場面を残す
- ブックも踏破時にドロップ確定し、全滅した周回の未確定分は失う。装備用の自動分解フィルターをブックへ自動適用しない
- 通常探索とオフライン進行に共通のドロップ定義を利用する。ブックの出現率は装備の確率と別途調整する

| レア度 | ツリーの質の方向性 | 鑑定費用の調整案（強化石） |
| --- | --- | ---: |
| N | 基礎能力・簡単な派生 | 20 |
| R | 攻撃／防御など役割が明確 | 50 |
| SR | 吸血・会心・反撃などのシナジー | 120 |
| UR | 条件付き強化・独自のギミック | 300 |
| LR | 強い個性と明確なメリット／デメリット | 800 |

費用・分岐数・個別効果は確定値ではない。反撃や状態異常など現行エンジンが扱えない効果は、対応機構の実装・検証後に公開する。

### 3.16 一次職の極み（採用済み・未実装、後続アップデート）
- 基本職6種（せんし／まほうつかい／そうりょ／とうぞく／ぶとうか／あんこくし）を終盤でも選ぶ理由を作る
- 上級職を基本職の完全な上位互換にせず、**基本職はビルド自由度・ブック適性、上級職は専門性能・固有能力**で差別化する。現行の数値がすでにこのバランスを満たしているとは扱わない
- 対象基本職を**Lv99以上**まで育てたキャラに、その基本職自体の強化を解放する。別ジョブへの転職ではなく同一ジョブの成長要素とする
- 既存の「基本職Lv50で上級職解放」と「Lv99で極み解放」を別条件として管理する。Lv99を新たなレベル上限とする変更は含めない
- 極みの進行はキャラごと・基本職ごとに保持し、上級職へ転職しても失わない。効果は対象基本職を使用中のみ有効とする
- 基本職のツリー適性強化を軸に設計する。追加SPやパッシブ倍率（+5%／+10%など）は調整案であり、確定性能として告知しない
- スキルツリー／スキルブックと同時に全開放せず、プレイヤーの育成状況・コンテンツ消費・品質を見て後から公開する

### 3.17 冒険者ギルドからのお知らせ（実装済み）
- 運営告知の正式名称を**「冒険者ギルドからのお知らせ」**とする
- 起動してタイトルが表示された時点で、公開対象の未読告知があれば最新の1件を自動モーダル表示する。現行はアカウント・認証なしのため「ログイン時」はこの起動時を指す
- タイトル右上に**手紙アイコン**を常設する。未読がある場合は赤丸を表示し、アイコンから一覧・詳細を再確認できる
- プレイ開始後も設定画面から同じお知らせへアクセスできる。タイトルに戻れない現行導線を補う
- 一覧に「お知らせ」「今後の予定」の2タブを設ける。「今後の予定」を独立した設定ページに重複作成しない
- カテゴリは「📢お知らせ／✨アップデート／🔧調整／🔮予告」の4種類。カテゴリと重要度は独立管理する
- 日付の降順で一覧表示し、各詳細は日付・カテゴリ・タイトル・本文を表示する。詳細表示が完了した告知だけ既読にし、一覧を開いただけで全件既読にはしない
- 既読は端末に保存し、通常告知は次回起動時に再表示しない。同じ告知を重要な内容へ改訂した場合は改訂単位で未読に戻せる
- 重要告知は明示的な再表示指定を認めるが、表示は1起動につき1件に抑える。再描画やバックグラウンド復帰だけで繰り返し表示しない
- オフライン報酬の計算・保存を済ませてから表示する。お知らせと「おかえりなさい」のモーダルはキューで順に表示し、重ねない
- 未公開・公開終了の告知は表示対象から除外し、通信や告知データの読み込み失敗でもプレイ開始を妨げない

### 3.18 段階リリース・予告公開（機能フラグ・予定表示は実装済み。予告の段階解禁は運用）
- **実装完了とプレイヤーへの公開を別管理**し、先行実装した機能をタイミングを見て順次公開する
- セーブ互換領域・機能ゲート・告知表示の土台を先に準備し、機能本体は個別feature branchで開発・検証する。リリース前にmainへ組み込む場合もUI・ドロップ・使用・戦闘効果・オフライン報酬の全経路をゲートする
- 機能の公開は運営のリリース判断で行う。端末時計が予定日を越えただけでは未公開機能を自動解放しない
- 基本的な公開順は「ギルドのお知らせと互換基盤 → スキルツリー → スキルブック・鑑定所 → 一次職の極み」。高難易度ダンジョンなどは将来構想とする
- ゲーム内の予定表示は「実装済／開発中／公開予定」の3状態。実装済はプレイヤーが利用できる公開済み機能を意味する。実装を検討するだけの構想は公開しない
- 月や日付はリリース計画を決めてから登録する。会話中の10月／11月／12月・12月15日は表示例であり約束した日程ではない
- 公開前の情報は「伏せ字の予告 → 名称・対象 → 解放条件・一部能力 → 当日全仕様」の順で解禁する。育成準備できるよう、Lv99条件は公開前に知らせる

| 公開までの目安 | 一次職の極みの告知内容 |
| --- | --- |
| 2〜3週間前 | 「？？？」「極めし者に、新たな道が開かれる。」 |
| 約1週間前 | 正式名称と基本6職が対象であること |
| 2〜3日前 | 基本職Lv99以上の条件・検証済みの一部能力 |
| 当日 | 全仕様、利用方法、公開済み状態 |

上記は告知運用の目安であり、必ず各段階を指定日に実行する自動配信仕様ではない。

## 4. 非機能要件

- **パフォーマンス**: `requestAnimationFrame` ベースのATBループで滑らかに戦闘を進行させる。x1/x2の再生速度切り替えに対応
- **オフライン耐性**: ネットワーク接続なしでも起動・プレイ可能（静的アセットのみで完結）
- **データ損失耐性**: 複数レイヤーの保存トリガーにより、ブラウザを閉じても進行状況の消失を最小化する
- **キャッシュ更新対策**: GitHub Pages/Safariのキャッシュにより更新が反映されない問題への対策として、`index.html` の `css`/`js` 読み込みに `?v=N` のキャッシュバスティング用クエリを付与し、更新のたびにバージョン番号を上げる運用とする
- **著作権保護**: 特定タイトルの固有名詞・グラフィック・具体的な文章表現・データ数値体系を流用しない。ジャンル共通のUI/UXパターンのみを参考にする

## 5. 将来構想・対象外（現時点で実装しない機能）

- 汎用の状態異常・バフ/デバフの仕組み（現行の技は「ダメージ／回復／吸収」の組み合わせ。採用済みツリーで必要になる機構は別途実装する）
- 所持品の並べ替え・上限・手動分解
- ストーリー要素
- グラフィック・SE/BGMの作り込み（現状はプレースホルダーのUIでシステムの面白さを検証する段階）
- iOSネイティブ化（Capacitor / Swift / Unity / Godot 等での書き直し）

これらは README.md の「今後の検討事項」として継続的に管理する。
